# `const`

## Концепты

- Константные переменные и объекты структур
- Копирование константного значения в неконстантный объект
- Константные ссылки: чтение, наблюдение изменений и копирование значений
- Константные параметры функций: передача по значению и по ссылке
- Чтение через указатель на константный объект, перенаправление указателя и наблюдение изменений
- Почему копирование адреса не снимает `const` с объекта
- Константные элементы C-массива
- Размеры массивов, известные во время компиляции: `const int` и структуры с `constexpr`

## Вопросы на понимание

Для каждого примера определите, скомпилируется ли он. Если да, что выведется?
Какие объекты можно менять и через какие выражения?

Если `main` не показан, поместите код внутрь `main`. Во всех примерах подключите `<iostream>` перед кодом:

```cpp
#include <iostream>

int main()
{
    // snippet here
}
```

### 1. Перезапись константной переменной

```cpp
const int a = 5;
a = 6;
std::cout << a << std::endl;
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: `a = 6` пытается изменить константный объект.
При инициализации `a` получает значение, но после этого присваивать ему новое значение нельзя.
Если убрать присваивание, выведется `5`.
</details>

### 2. Копирование константного числа

```cpp
const int a = 5;
int b = a;
b = 6;
std::cout << a << std::endl;
std::cout << b << std::endl;
```

<details>
<summary>Ответ</summary>

Выведутся `5` и `6`.
`b` — отдельный неконстантный объект, в который при инициализации копируется значение `a`.
Читать константный объект можно; изменение копии не меняет оригинал.
</details>

### 3. Константный объект структуры

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    const Position a{ 1, 2 };
    a.x = 3;
    std::cout << a.x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: `a.x = 3` пытается изменить поле константного объекта `a`.
Сами поля объявлены как обычные `int`; константным является именно этот объект типа `Position`.
Если убрать присваивание, выведется `1`.
</details>

### 4. Копирование константной структуры

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    const Position a{ 1, 2 };
    Position b = a;
    b.x = 3;
    std::cout << a.x << std::endl;
    std::cout << b.x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `1` и `3`.
Как и с `int`, константный объект можно скопировать в неконстантный.
Значения полей копируются в `b`; `b.x` и `a.x` — разные объекты.
</details>

### 5. Запись через константную ссылку

```cpp
const int a = 5;
const int& r = a;
r = 6;
std::cout << r << std::endl;
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: `r = 6` пытается изменить `a` через константную ссылку.
`r` ссылается на существующий объект `a`, а не хранит копию его значения.
`const int&` может ссылаться на константное число, но через такую ссылку разрешено только чтение.
Если убрать присваивание, выведется `5`.
</details>

### 6. Наблюдение изменения через константную ссылку

```cpp
int a = 5;
const int& r = a;
std::cout << r << std::endl;
a = 6;
std::cout << r << std::endl;
```

<details>
<summary>Ответ</summary>

Выведутся `5` и `6`.
Константная ссылка может ссылаться и на неконстантный объект.
`a` по-прежнему можно менять напрямую, а через `r` читается текущее значение того же объекта.
Ограничение запрещает запись через `r`, но не делает `a` неизменяемым.
</details>

### 7. Копирование значения, прочитанного через константную ссылку

```cpp
int a = 5;
const int& r = a;
int b = r;
b = 6;
a = 7;
std::cout << r << std::endl;
std::cout << b << std::endl;
```

<details>
<summary>Ответ</summary>

Выведутся `7` и `6`.
`int b = r` копирует значение, прочитанное через `r`, в отдельный неконстантный объект.
Изменение `b` не меняет `a`, а изменение `a` не меняет `b`.
Ссылка `r` продолжает ссылаться на `a`.
</details>

### 8. Попытка создать неконстантную ссылку через константную

```cpp
int a = 5;
const int& r = a;
int& other = r;
other = 6;
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется на строке `int& other = r`.
Нельзя получить неконстантную ссылку на объект через константную ссылку, отбросив `const`.
В отличие от `int b = r`, новый отдельный объект типа `int` здесь не создавался бы: `other` ссылалась бы на тот же объект и позволяла бы менять его.
Правило действует, даже если именно этот объект `a` неконстантный.
Можно написать `const int& other = r`, сохранив ограничение; тогда `other = 6` тоже будет запрещено.
</details>

### 9. Поля структуры через константную ссылку

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    Position a{ 1, 2 };
    const Position& r = a;
    r.x = 3;
    std::cout << r.x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: `r.x = 3` пытается изменить целочисленное поле через константную ссылку.
То же правило доступа только для чтения действует и для всей структуры.
`a.x = 3` было бы разрешено, потому что сам объект `a` неконстантный.
Если убрать присваивание, выведется `1`.
</details>

### 10. Константный параметр по значению

```cpp
void func(const int a)
{
    a = 6;
}

int main()
{
    int a = 5;
    func(a);
}
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: параметр `a` внутри `func` константный.
При вызове значение аргумента копировалось бы в этот отдельный объект-параметр.
`const` у параметра запрещает менять копию, но не делает переменную в вызывающей функции константной.
То же правило действует для структуры, переданной по значению как `const Position a`.
</details>

### 11. Константный аргумент и неконстантный параметр

```cpp
void func(int a)
{
    a = 6;
    std::cout << a << std::endl;
}

int main()
{
    const int a = 5;
    func(a);
    std::cout << a << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `6` и `5`.
Константный аргумент копируется в обычный параметр типа `int`.
Меняется только локальная копия, как в предыдущем примере с копированием числа.
</details>

### 12. Передача константной структуры по значению

```cpp
struct Position
{
    int x;
    int y;
};

void func(Position a)
{
    a.x = 3;
    std::cout << a.x << std::endl;
}

int main()
{
    const Position a{ 1, 2 };
    func(a);
    std::cout << a.x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `3` и `1`.
Здесь объединяются копирование структуры и передача по значению.
Параметр — неконстантная копия: менять его поле можно, и на оригинал это не влияет.
</details>

### 13. Параметр — константная ссылка

```cpp
struct Position
{
    int x;
    int y;
};

int readX(const Position& a)
{
    return a.x;
}

int main()
{
    Position a{ 1, 2 };
    const Position b{ 3, 4 };
    std::cout << readX(a) << std::endl;
    a.x = 5;
    std::cout << readX(a) << std::endl;
    std::cout << readX(b) << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `1`, `5` и `3`.
В [лабораторной по ссылкам](11_reference.md) параметр структуры с `&` использовался для изменения объекта в вызывающей функции.
При добавлении `const` ссылка на исходный объект сохраняется, но через параметр его можно только читать.
При каждом из этих вызовов объект типа `Position` не копируется.

Параметру типа `const Position&` можно передавать как константные, так и неконстантные объекты.
Второй вызов читает обновлённое значение `a.x`, а если добавить `a.x = 6` внутри `readX`, возникнет ошибка компиляции.
Параметр по значению `Position a` создавал бы отдельную изменяемую копию, как в предыдущем примере.
</details>

### 14. Указатель на константный объект

```cpp
int a = 5;
const int* p = &a;
*p = 6;
std::cout << *p << std::endl;
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: `*p = 6` пытается записать значение через указатель на константный объект.
Через `const int*` можно читать число, на которое он указывает, но нельзя менять его через `p`.
Если убрать присваивание, выведется `5`.
</details>

### 15. Перезапись указателя на константный объект

```cpp
int a = 5;
int b = 6;
const int* p = &a;
p = &b;
std::cout << *p << std::endl;
```

<details>
<summary>Ответ</summary>

Выведется `6`.
Объект, к которому обращаются через `p`, нельзя менять через этот указатель, но сам `p` менять можно.
Присваивание `&b` меняет сохранённый адрес, а не значения чисел.
</details>

<details>
<summary>Где ставить <code>const</code>?</summary>

`const int* p` и `int const* p` означают одно и то же: указатель на константный `int`.
Здесь `const` относится к объекту, на который указывает `p`.

В `int* const p = &a` слово `const` относится к самой переменной-указателю:
`p = &b` запрещено, но `*p = 6` разрешено, если `a` неконстантный.
`const int* const p = &a` запрещает оба изменения.

В этой лабораторной основной акцент на `const T*`: чтении объекта через указатель.
</details>

### 16. Доступ к полям структуры через указатель на константный объект

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    Position a{ 1, 2 };
    const Position* p = &a;
    p->x = 3;
    std::cout << p->x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: `p->x = 3` пытается изменить объект через `const Position*`.
Через `p` можно читать оба целочисленных поля, но нельзя менять ни одно из них.
Если убрать присваивание, выведется `1`.
</details>

### 17. Наблюдение изменения через указатель на константный объект

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    Position a{ 1, 2 };
    const Position* p = &a;
    std::cout << p->x << std::endl;
    a.x = 3;
    std::cout << p->x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `1` и `3`.
`a` остаётся неконстантным объектом, и его можно менять напрямую.
Указатель не хранит застывшую копию `a`: при каждом чтении он обращается к текущему значению поля того же объекта.
`const Position*` ограничивает доступ через этот указатель, а не все способы обращения к `a`.
</details>

### 18. Копирование адреса не копирует объект

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    Position a{ 1, 2 };
    const Position* p = &a;
    Position* q = p;
    q->x = 3;
}
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется на строке `Position* q = p`.
Нельзя инициализировать обычный указатель из указателя на константный объект, отбросив `const` у объекта.

В отличие от `Position b = a`, копирование указателя копирует адрес, а не объект типа `Position`.
Если бы такое преобразование было разрешено, через `q` можно было бы менять тот же объект.
Можно написать `const Position* q = p`, сохранив ограничение; тогда `q->x = 3` тоже будет запрещено.
Преобразование запрещено, даже если именно этот объект `a` неконстантный.
</details>

### 19. Копирование значения, прочитанного через указатель на константный объект

```cpp
struct Position
{
    int x;
    int y;
};

int main()
{
    const Position a{ 1, 2 };
    const Position* p = &a;
    Position b = *p;
    b.x = 3;
    std::cout << p->x << std::endl;
    std::cout << b.x << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `1` и `3`.
`Position b = *p` читает и копирует весь объект, а не его адрес.
Новый объект `b` неконстантный, поэтому его поля можно менять.
Здесь чтение через указатель объединяется с уже знакомым правилом копирования структуры.
</details>

### 20. Параметр-указатель на константный объект

```cpp
struct Position
{
    int x;
    int y;
};

int readX(const Position* p)
{
    return p->x;
}

int main()
{
    Position a{ 1, 2 };
    const Position b{ 3, 4 };
    std::cout << readX(&a) << std::endl;
    std::cout << readX(&b) << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `1` и `3`.
Функция получает копию адреса, а не копию структуры.
Она может читать исходный объект, но не может менять его целочисленные поля через `p`.
Если добавить `p->x = 5` внутри `readX`, возникнет ошибка компиляции.
Параметру типа `const Position*` можно передать адрес как неконстантного, так и константного объекта.
Сам локальный параметр-указатель по-прежнему можно перенаправить, как в предыдущем примере с указателем.
</details>

### 21. Константный C-массив

```cpp
const int arr[2]{ 1, 2 };
arr[0] = 3;
std::cout << arr[0] << std::endl;
```

<details>
<summary>Ответ</summary>

Программа не скомпилируется: элементы `arr` — константные числа.
Их можно читать, но `arr[0] = 3` пытается изменить один из них.
Если убрать присваивание, выведется `1`.
</details>

### 22. Чтение массива через указатель на константный объект

```cpp
int arr[2]{ 1, 2 };
const int* p = arr;
arr[0] = 3;
std::cout << p[0] << std::endl;
p += 1;
std::cout << *p << std::endl;
```

<details>
<summary>Ответ</summary>

Выведутся `3` и `2`.
C-массив даёт адрес своего первого элемента.
`p[0]` читает текущее значение `arr[0]`, которое изменили напрямую.
Указатель можно передвинуть к следующему элементу, но ни `p[0] = 4`, ни `*p = 4` не разрешены.
Здесь доступ к массиву и арифметика указателей объединяются с чтением через указатель на константный объект.
</details>

### 23. Константные числа в качестве размеров массивов

```cpp
const int globalSize = 2;

int main()
{
    const int localSize = 3;
    int a[globalSize]{ 1, 2 };
    int b[localSize]{ 3, 4, 5 };
    std::cout << a[1] << std::endl;
    std::cout << b[2] << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведутся `2` и `5`.
Оба размера — константные числа, инициализированные константными выражениями, поэтому их значения можно использовать во время компиляции.
Глобальная переменная не обязательна: локальный `localSize` тоже подходит.
Здесь речь о размере, известном во время компиляции, а не о ключевом слове `static`.
</details>

### 24. Константное значение не всегда известно во время компиляции

```cpp
int input = 0;
std::cin >> input;
const int size = input;
int arr[size]{};
```

<details>
<summary>Ответ</summary>

В стандартном C++ программа не скомпилируется на строке `int arr[size]{}`.
`size` нельзя перезаписать, но его значение получено от пользователя и не является константным выражением.
Для такого C-массива компилятору нужен размер, известный во время компиляции.
Некоторые компиляторы поддерживают массивы переменной длины как расширение, но это не стандартный C++.
</details>

### 25. Структура с constexpr и размер массива

```cpp
struct Sizes
{
    int count;
};

int main()
{
    constexpr Sizes sizes{ 3 };
    int arr[sizes.count]{ 1, 2, 3 };
    std::cout << arr[2] << std::endl;
}
```

<details>
<summary>Ответ</summary>

Выведется `3`.
Переменная с `constexpr` должна быть инициализирована константным выражением и также является константной.
Здесь весь объект типа `Sizes` инициализирован во время компиляции, поэтому `sizes.count` можно использовать как размер массива.

В предыдущем случае `const int localSize = 3` слово `constexpr` не требовалось, чтобы использовать значение как размер.
Для этой структуры одного `const Sizes sizes{ 3 }` недостаточно: `sizes.count` не станет константным выражением, пригодным для размера массива.
`constexpr` явно даёт такую гарантию для этого объекта.

В [лабораторной по массивам C++](13_cpp_array.md) та же идея используется для аргумента размера в `std::array<int, sizes.count>`.
</details>
