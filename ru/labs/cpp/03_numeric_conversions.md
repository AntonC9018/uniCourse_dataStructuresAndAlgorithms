### 1. `auto` и `static_cast`

```cpp
auto a{ static_cast<uint8_t>(5) };
```

<details>
<summary>Что делает <code>static_cast&lt;uint8_t&gt;</code>?</summary>

`static_cast<uint8_t>(5)` это выражение,
результатом которого является число `5` типа `uint8_t`.

- `static_cast` говорит, "конвертируй результат выражения из одного типа в другой".
- `<uint8_t>` показывает, в какой тип нужно переконвертировать.
- `(5)` в скобках задается выражение, результат которого нужно переконвертировать.

То есть произойдет следующее:
- Вычисляется выражение из круглых скобок (`(5)`), получаем число `5` типа `int`.
- Выполняется `static_cast` в тип, указанный внутри `<...>`, то есть в `uint8_t`.
  Поскольку `5` влезает в 1 байт, конвертируется без проблем.
- `static_cast<uint8_t>(5)` заменяется на число `5` типа `uint8_t`.
- `auto` воспринимает тип присваиваемого выражения, заменяется на `uint8_t`.
</details>

### 2. `static_cast` в больший тип

```cpp
uint8_t a{ 5 };
int b{ static_cast<int>(a) };
```

<details>
<summary>Ответ</summary>

`static_cast<int>` здесь произойдет даже если его не написать.
Так как любое число, сохраненное в `a`, всегда влезет в `b`,
можно просто присвоить к `b` переменную `a`,
что совершит конверсию из `uint8_t` в `int` автоматически.
</details>

### 3. `static_cast` отрицательного числа в больший тип

```cpp
int8_t a{ -3 };
int b{ static_cast<int>(a) };
```

<details>
<summary>Ответ</summary>

Как и в прошлом примере, конверсия произойдет автоматически даже без `static_cast`,
потому что любое число, сохраненное в `a`, влезет в `b`.

Конверсия сохраняет значение, а значит и знак:
раз `a` отрицательное, верхние биты `b` заполнятся 1.
`-3` это `1111 1101` в 8 битах
и `1111 1111 1111 1111 1111 1111 1111 1101` в 32 битах.
</details>


### 4. `static_cast`
```cpp
#include <cstdint>
#include <iostream>

int main()
{
    uint32_t a{ 256 };
    uint8_t b{ static_cast<uint8_t>(a) };
    uint32_t c{ b };
    std::cout << c << std::endl;
}
```

<details>
<summary>Что делает <code>static_cast&lt;uint8_t&gt;</code>?</summary>

В данном примере, он берет только младший байт числа от `a`,
отсекая старшие 3 байта. Это называется truncation.

Если записать это без `static_cast<uint8_t>`,
по умолчанию он произойдет автоматически.
При этом компилятор не дает ошибок,
если не переданы флаги предупреждения при компиляции.

> Чтобы подобные ситуации определялись и останавливались компилятором,
> необходимо передать флаги предупреждений, компилируя, например, вот так:
> ```
> g++ test.cpp -Wall -Werror -Wconversion
> ```
>
> Помимо этого, можно использовать инициализацию через фигурные скобки.
> Следующее тоже не скомпилируется:
> ```cpp
> uint8_t b { 256 }; // сужающее преобразование
> ```
>
> А следующее вероятно даст предупреждение:
> ```cpp
> uint32_t a { 256 };
> uint8_t b { a }; // сужающее преобразование
> ```


</details>

<details>
<summary>Правильный ответ:</summary>

`static_cast<uint8_t>` обрезает значение `a` (truncation),
оставляя только последний байт (наименьший байт).

Ответ будет 0, потому что число 256 имеет запись `1 0000 0000` в двоичной системе,
а обрезание этого числа до 8 бит оставит лишь `0000 0000`,
удалив старшую 1.

То же значение со всеми 32 битами, под каждыми 4 битами написана их 16-чная цифра:
```
0000 0000  0000 0000  0000 0001  0000 0000
0    0     0    0     0    1     0    0
```

Как читать эту запись: в верхней строке биты, разбитые на группы по 4
(одна группа на 16-чную цифру, между целыми байтами промежуток пошире);
в нижней строке под каждыми 4 битами стоит их 16-чная цифра.
Читая нижнюю строку, получаем `0x00000100`, то есть 256.
При обрезании до `uint8_t` остается только последний байт (`0000 0000`), поэтому ответ 0.
</details>

<details>
<summary>Что будет, если в <code>a</code> сохранить другое значение?</summary>

- Значение 257: Сохранится `1 0000 0001`, что оставит `0000 0001` при отсечении.
- Значение 258: Сохранится `1 0000 0010`, что оставит `0000 0010` при отсечении.
- Значение 511: Сохранится `1 1111 1111`, что оставит `1111 1111` при отсечении.
- Значение 512: Сохранится `10 0000 0000`, что оставит `0000 0000` при отсечении.
</details>

### 5. Побитовая операция (продвинутый уровень)
```cpp
#include <cstdint>
#include <iostream>

int main()
{
    uint8_t a{ 0 };
    uint8_t b{ ~a };
    int32_t c{ b };
    std::cout << c;
}
```

<details>
<summary>

Что делает `~`?

</summary>

Это побитовый оператор, который переделывает все 0 в 1 в двоичном представлении числа.
Например, `1010 0011` -> `0101 1100`.
</details>

<details>
<summary>Правильный ответ</summary>

- 0 сохраняется в переменную на 8 бит.
- Оператор `~` применится на 8-битный 0: `0000 0000` -> `1111 1111` (255)
- Результат сохраняется в 8-битную `b`.
- Результат пересохраняется как есть в 32-битный `c` (для печати).

Та же запись, под каждыми 4 битами их 16-чная цифра:
```
a:
0000 0000
0    0

b:
1111 1111
F    F

c:
0000 0000  0000 0000  0000 0000  1111 1111
0    0     0    0     0    0     F    F
```

Поскольку `b` без знака, старший бит считается обычным положительным битом,
поэтому старшие 3 байта `c` заполнятся 0 (zero extension):
в `c` окажется `0x000000FF`, и программа напечатает 255.
Тип со знаком, наоборот, воспринимает старший бит как имеющий отрицательный коэффициент,
поэтому при расширении отрицательного значения верхние биты заполняются 1.

</details>

### 6. Смена знака (продвинутый уровень)
```cpp
#include <cstdint>
#include <iostream>

int main()
{
    uint8_t a{ 127 };
    int8_t b{ static_cast<int8_t>(a) };
    int32_t c{ b };
    std::cout << c;
}
```

<details>

<summary>

Что делает `static_cast<int8_t>`?

</summary>

В данном примере, он воспринимает представление числа сохраненное в `a` как есть, но со знаком.

Например, если `a` равен 0, в ответе будет 0, потому что `0000 0000`
что как целое со знаком, что без знака, является значением 0.

Если `a` равен 128, то есть `1000 0000`, станет `-128`, потому что `1000 0000`
как число со знаком это -128.
</details>

<details>

<summary>

Что делает присваивание к `int32_t` для меньшего типа со знаком `int8_t`?

</summary>

Если значение отрицательное, ответ тоже будет отрицательным (верхние биты заполнятся 1).
Например, -1 записывается как `1111 1111` в 8 битах,
станет `1111 1111 1111 1111 1111 1111 1111 1111` в 32 битах,
что тоже равно -1.

Если значение положительное, ответ тоже будет положительным (верхние биты заполняются 0).
Например, 10 записывается как `0000 1010` в 8 битах,
станет `0000 0000 0000 0000 0000 0000 0000 1010` в 32 битах,
что тоже равно 10.

Короче говоря, в `int32_t` будет всегда храниться *то же числовое значение*.
</details>

<details>
<summary>Правильный ответ:</summary>

- 127 записывается в `a` как `0111 1111`.
- `0111 1111` конвертируется как есть в `b`, а `0111 1111` как число со знаком — 127
- значение 127 сохраняется в `c` как значение 127 (см. выше объяснение как).

Та же запись, под каждыми 4 битами их 16-чная цифра:
```
a, b:
0111 1111
7    F

c:
0000 0000  0000 0000  0000 0000  0111 1111
0    0     0    0     0    0     7    F
```

Поскольку `b` положительное, старшие 3 байта `c` заполнятся 0:
в `c` окажется `0x0000007F`, поэтому программа напечатает 127.
</details>
