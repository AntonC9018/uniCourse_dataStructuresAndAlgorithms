# Массивы

## О C-массивах

C-массивы — это те массивы, с которыми мы познакомились в предыдущей главе.
Напомним: вот пример C-массива:

```cpp
int a[4];
```

Они поддерживают оператор индексации и представляют собой линейный блок памяти.


### Функции, принимающие массивы как аргументы

Передать C-массив в функцию на самом деле нельзя.
Можно передать только адрес памяти массива.


### Пример с суммой

Например, определим функцию `sum`, которая принимает адрес
первого элемента некоторого массива и суммирует все элементы по очереди,
возвращая сумму как результат.
Заметьте: функция должна знать, сколько элементов в этом блоке.

```cpp
int sum(int* a)
{
    int result = 0;
    for (size_t i = 0; i < 4; i++)
    {
        int* pointerToElement = a + i;
        int elementAtIndex = *pointerToElement;
        result = result + elementAtIndex;
    }
    return result;
}
```

Прототип функции может быть и таким:

```cpp
int sum(int a[]);
```

это означает то же самое.
Я буду придерживаться записи через указатель, поскольку второй вариант мне кажется бессмысленным.


Теперь попробуем вызвать эту функцию:
```cpp
int main()
{
    // Заметьте: длина должна в точности совпадать с той, что используется в функции.
    int arr[4]{};
    arr[0] = 5;
    arr[1] = 10;

    // Передаем ей указатель на начало памяти массива.
    int result = sum(&arr[0]); // 15

    // При передаче переменной-массива неявно передается адрес первого элемента.
    // Это также называют «распадом» (decay) массива в указатель.
    int result1 = sum(arr); // 15

    return 0;
}
```

### Порча стека

Заметьте: если ошибиться с длиной массива,
например, сделать массив в `main` короче, чем ожидает функция,
компилятор не выдаст никаких предупреждений.
Более того, весьма вероятно, что программа выполнится без проблем,
но выдаст мусорный результат.

Представим, что `main` выглядит так:

```cpp
int main()
{
    int arr[2]{};
    sum(arr);
}
```

Функция `sum` попытается суммировать память за пределами памяти, отведенной элементам массива,
то есть фактически прочитает память, которая лежит дальше на стеке.
Следующим за локальной переменной-массивом `arr` на стеке
скорее всего окажется адрес возврата функции `sum`.

> 🤓 что именно лежит рядом с массивом (и лежит ли там адрес возврата) —
> деталь реализации раскладки стека. Стандарт технически вообще не обещает,
> что память за пределами массива можно читать или писать: это неопределенное поведение.
> На практике же на любом современном железе со стандартной раскладкой стека
> за локальными переменными действительно лежат служебные данные кадра,
> включая адрес возврата.

А теперь представьте, что функция `sum` пишет в эту память, а не просто читает из нее.

```cpp
void setZeros(int* a)
{
    for (size_t i = 0; i < 4; i++)
    {
        a[i] = 0;
    }
}
```

При неверном размере это может привести к *порче стека* (stack corruption) —
адрес возврата на стеке может быть перезаписан нулями,
и программа упадет, когда функция попытается вернуться.

Порча стека означает вмешательство в память за пределами той, что ожидаемо доступна.


### Передача длины как параметра

Чтобы этого избежать, всегда передавайте длину вместе с указателем.
Полный пример см. в [array.cpp](../../en/06_arrays/array.cpp).

Чтобы не повторять длину несколько раз,
можно либо завести константу с ней, вот так (нормально):

```cpp
const size_t arrayLength = 4;

int main()
{
    int arr[arrayLength]{};
    sum(arr, arrayLength);
    return 0;
}
```

Либо использовать `define` (так делать не надо):
    
```cpp
#define ARRAY_LENGTH 4UL

int main()
{
    int arr[ARRAY_LENGTH]{};
    sum(arr, ARRAY_LENGTH);
    return 0;
}
```

Либо вычислить её во время компиляции в месте вызова с помощью `sizeof`.
`sizeof(arr)` дает длину всего массива в байтах, и её нужно
разделить на размер одного элемента `sizeof(arr[0])`,
чтобы получить число элементов.

```cpp
int main()
{
    int arr[4]{};
    sum(arr, sizeof(arr) / sizeof(arr[0]));
    return 0;
}
```

В C++ есть еще один вариант: параметр шаблона (без особых подробностей).
По сути, компилятор может понять длину из типа массива.

```cpp
template<size_t N>
int sum(int (&arr)[N])
{
    int result = 0;
    for (size_t i = 0; i < N; i++)
    {
        result += arr[i];
    }
    return result;
}

int main()
{
    int arr[4]{};
    sum(arr);
    return 0;
}
```

### Разбиение массива компьютеров на массивы частей

Магазин ведет учет компьютеров, которые продает.
Каждый компьютер состоит из монитора, системного блока и клавиатуры,
поэтому естественно хранить их массивом структур:

```cpp
#include <cstdint>

struct Monitor
{
    uint16_t widthPixels;
    uint16_t heightPixels;
};

struct SystemUnit
{
    double priceInDollars;
    uint64_t serialNumber;
};

struct Keyboard
{
    uint8_t rows;
    uint8_t columns;
};

struct Computer
{
    Monitor monitor;
    SystemUnit systemUnit;
    Keyboard keyboard;
};
```

Части занимают 4, 16 и 2 байта — всего 22 байта полезных данных.
Один `Computer` при этом занимает 32 байта на x86-64:

| Смещение | Размер | Что лежит     |
|----------|--------|---------------|
| 0        | 4      | `monitor`     |
| 4        | 4      | пустые байты  |
| 8        | 16     | `systemUnit`  |
| 24       | 2      | `keyboard`    |
| 26       | 6      | пустые байты  |

В системном блоке лежат `double` и `uint64_t`, а ABI требует, чтобы оба начинались
по адресу, кратному 8. Так работает выравнивание (alignment). Монитор заканчивается
на смещении 4, поэтому компилятор пропускает 4 байта и кладет системный блок на смещение 8.
Размер самой структуры тоже должен быть кратен 8, иначе следующий элемент массива
`Computer` оказался бы на невыровненном адресе. На это уходят последние 6 байт.

Получается, на пустые байты (padding) уходит 10 из 32 байт каждого компьютера,
почти треть массива.

При этом части одного компьютера вовсе не обязаны лежать рядом.
Можно завести для каждой части свой массив, и тогда компьютер с индексом `i`
будет состоять из `monitors[i]`, `systemUnits[i]` и `keyboards[i]`:

```cpp
int main()
{
    constexpr size_t numComputers = 1000;

    // Один массив целых компьютеров: по 32 байта на каждый.
    Computer computers[numComputers]{};
    size_t bytesOfComputers = sizeof(computers); // 32000

    // Три массива частей: 4 + 16 + 2 = 22 байта на каждый.
    Monitor monitors[numComputers]{};
    SystemUnit systemUnits[numComputers]{};
    Keyboard keyboards[numComputers]{};
    size_t bytesOfParts =
        sizeof(monitors) + sizeof(systemUnits) + sizeof(keyboards); // 22000

    // Части компьютера с индексом 3 лежат в каждом массиве по индексу 3.
    monitors[3].widthPixels = 1920;
    systemUnits[3].priceInDollars = 999.99;
    keyboards[3].rows = 6;

    return 0;
}
```

В разбитом варианте пустых байтов нет: элементы массива лежат ровно на расстоянии
`sizeof(T)` друг от друга, а размер типа всегда кратен его выравниванию,
так что промежутки для выравнивания не нужны.
Поэтому тысяча компьютеров занимает 22 000 байт вместо 32 000,
и мы экономим 10 000 байт, то есть 31% памяти.
Это верно при условии, что внутри самих частей пустых байтов тоже нет,
а здесь это так.

Такое расположение называют *структурой из массивов* (struct of arrays):
три массива можно сделать полями одной структуры.
Начали же мы с *массива структур*.

Разбиение не бесплатно. Части одного компьютера больше не лежат рядом,
поэтому чтобы добраться до всех частей, нужно заглянуть в три разных места в памяти,
а три массива приходится держать согласованными: одинаковая длина, одинаковые индексы,
элементы добавляются и удаляются вместе.
Разбиение окупается, когда чаще нужна одна и та же часть от многих компьютеров,
например при подсчете суммарной цены всех системных блоков.
Такой цикл пройдет по 16 000 байтам `systemUnits`, половина из которых — серийные номера,
и не тронет ни одного монитора или клавиатуры, вместо всех 32 000 байт целых компьютеров.

> 🤓 Часть этих потерь связана с порядком полей.
> У системного блока самое строгое выравнивание, поэтому если поставить его первым,
> `Computer` сожмется до 24 байт: 16 на блок, 4 на монитор, 2 на клавиатуру
> и 2 пустых байта в конце. Сортировать поля от большего выравнивания
> к меньшему — первое, что стоит попробовать. Остаются только пустые байты в конце —
> не больше `alignof` самой структуры минус один байт на элемент, — и разбиение
> убирает и их. На практике между двумя расположениями выбирают исходя из того,
> какие части нужны вместе, а не только по пустым байтам.

Полный пример см. в [computer.cpp](../../en/06_arrays/computer.cpp).


## `std::array`

C++ добавляет несколько более удачных способов работать с линейными блоками памяти фиксированного типа.
Один из них — `std::array`.

`std::array` можно использовать вместо C-массивов, и у него куча преимуществ:
- Число элементов зашито в тип и доступно через `size()`;
- Это настоящий тип, а не особая сущность вроде массивов, то есть его можно
  передавать в функции без хаков;
- Он не распадается на указатель;
- Можно обычным образом получить указатель на блок памяти, если его тип — `std::array`
  (работает как обычный указатель), без дополнительного синтаксиса.
  ```cpp
  // Указатель на массив из 4 элементов
  std::array<int, 4>* p{ &arr };
  ```

> Примечание: я даже не объясняю замысловатый дополнительный синтаксис, используемый для C-массивов,
> потому что не считаю его полезным.

### Пример

> Примечание: запись `Type variableName = { }` эквивалентна `Type variableName{ }`.

```cpp
// Подключите этот заголовок, чтобы использовать std::array.
#include <array>

int main()
{
    std::array<int, 4> arr{};

    // В памяти это выглядело бы так же, как:
    // int arr[4]{};

    // Оператор индексации используется как обычно.
    arr[0] = 5;

    // Можно брать указатели на элементы, как обычно.
    int* pointerToElement = &arr[2];

    // А поскольку это обычный тип, можно скопировать
    // весь массив одной операцией.
    // При этом создается еще один блок памяти на 4 int,
    // и каждый int копируется из `arr`.
    std::array<int, 4> copy = arr;

    // Длина входит в тип, поэтому массивы разного размера —
    // несовместимые типы, и присвоить один другому нельзя,
    // причем неважно, больше целевой массив исходного или меньше.
    std::array<int, 8> larger{};
    std::array<int, 2> smaller{};
    // larger = arr;  // Ошибка: std::array<int, 4> — не std::array<int, 8>
    // smaller = arr; // Ошибка: std::array<int, 4> — не std::array<int, 2>
    // arr = larger;  // Ошибка: std::array<int, 8> — не std::array<int, 4>
    // arr = smaller; // Ошибка: std::array<int, 2> — не std::array<int, 4>

    // И еще немного магии: на самом деле он способен сам понять,
    // что вы имели в виду тип `int` и длину,
    // если использовать инициализацию фигурными скобками с конкретными значениями.
    std::array arr2{1, 2, 3, 4};
    // Что эквивалентно
    // std::array<int, 4> arr2{1, 2, 3, 4};

    // То же произойдет при попытке скопировать:
    std::array copy2 = arr2;

    // Приятно то, что 4 больше не нужно нигде захардкодивать,
    // и не нужен хак с `sizeof`, благодаря `.size()`:
    size_t numElementsOfArray = arr.size(); // 4

    // Это сработает даже в контексте const (и даже constexpr),
    // потому что `.size()` известен из типа во время компиляции.
    // Это полезно, когда длину массива нужно использовать
    // во время компиляции, например, как размер массива.
    constexpr size_t numElementsOfArray2 = arr.size(); // 4

    // Можно иметь указатель на `std::array` фиксированного размера,
    // чего с C-массивами не сделать (без особого синтаксиса).
    std::array<int, 4>* pointerToArray = &arr;
    (*pointerToArray)[1] = 9;
    int firstElement = arr[1]; // 9

    return 0;
}
```
