# Инструкции C++ и простые функции

Вы начнёте с одного сообщения, будете шаг за шагом менять его вывод, а затем организуете те же действия в функции, которые можно вызвать один раз, дважды или из другой функции.

Термины, которые понадобятся:

- **Машинный код** — низкоуровневый язык инструкций процессора. **Язык программирования**, здесь C++, позволяет описывать действия в читаемом исходном коде. **Абстракция** означает выражение низкоуровневых деталей через более простые понятия.
- **Память** хранит значения. **Ячейка памяти** — это место, в котором лежат данные; **адрес** идентифицирует место. **Регистр процессора** — небольшое хранилище внутри процессора. **Переменная** даёт программе имя, через которое можно работать со значением.
- **Инструкция программы**, обычно по-английски называемая **statement**, выражает действие в исходном коде. **Синтаксис** — это правила написания такого кода.
- **Функция** — именованная переиспользуемая последовательность инструкций. Её **определение** задаёт имя и инструкции; её **тело** — код в фигурных скобках, `{ }`. **main** — специальная функция, с которой начинается выполнение этих примеров.
- **Вызов функции** запускает выполнение тела функции. **Вызывающая** функция — та, которая делает этот вызов, а **место вызова** — точка в коде, где он записан. **Возврат** означает продолжение работы вызывающей функции после вызова. **Управляющий поток** (control flow) — это порядок, в котором выполнение переходит от одной инструкции к другой. **Вложенный вызов** происходит, когда одна вызванная функция вызывает другую.
- **Консоль** отображает текст; **терминал**, показанный в записи, обеспечивает этот вывод и место для запуска команд. **Строковый литерал** — это текст, записанный в двойных кавычках.
- **Стандартная библиотека** предоставляет общие возможности. **Заголовочный файл** делает объявления библиотеки доступными; `#include <iostream>` подключает заголовок, используемый для вывода в консоль. `std::cout` — стандартный поток вывода, а `<<` отправляет следующее значение в него.
- **Перевод строки** завершает текущую строку вывода. `std::endl` записывает перевод строки и сбрасывает поток, то есть отправляет накопленный в буфере вывод дальше.
- **Комментарий** — это текст исходника, который при обработке как кода игнорируется. `//` начинает комментарий, продолжающийся до конца своей строки исходного кода.
- **Исходный файл** содержит написанный вами код. **Компилятор** переводит исходный код; **компиляция** — этот перевод. **Компоновщик** объединяет скомпилированный код и нужный код библиотек в **исполняемый файл**, который можно запустить. **Компоновка** — этот шаг объединения, а **флаг** — опция, передаваемая команде сборки.
- `int` — целочисленный тип C++ и тип возвращаемого значения, используемый для `main`. `void` в качестве типа возврата функции означает, что она ничего не возвращает. **Параметр** — именованный вход функции; простые функции здесь не принимают параметров.
- Только ради уточнения о корректности ниже: **указатель** — это значение, в котором хранится адрес памяти. Работа с указателями в этом видео не рассматривается.

## От машинных инструкций к читаемым действиям

[00:00:21](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=21s) **Абстракция** означает упрощение чего-то непрозрачного за счёт выражения его в более понятных терминах. Вместо того чтобы расписывать низкоуровневые инструкции, вы пишете обычный исходный код, описывающий действие.

[00:00:37](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=37s) Работа с **памятью**, то есть хранилищем значений, включает операции вроде сложения чисел и копирования значения из одной ячейки памяти в другую. Ячейка памяти — это место, в котором хранятся данные. Вам также нужен способ указать, когда эти операции должны выполняться.

[00:00:54](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=54s) В записи объясняется, что эти учебные примеры напрямую не выбирают регистр процессора и не читают по выбранному фиксированному адресу. **Регистр** — это хранилище внутри процессора, а **адрес** идентифицирует место в памяти. Смысл урока в том, что доступ идёт через языковую абстракцию, а не через выбор мест в оборудовании вручную.

Здесь нужна оговорка: C++ всё же поддерживает доступ через **указатели** — значения, в которых хранятся адреса памяти, — если этот доступ корректен. Поэтому утверждение «нельзя прочитать по фиксированному адресу» является упрощением подхода этого урока, а не универсальным ограничением C++. [Связанное закоммиченное объяснение работы с памятью](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/e6a198dd9d5f56bde01e2f74f0d71bf253316d82/en/05_programming_fundamentals/doc.md#writing-to-a-memory-address) показывает это различие. Этот короткий пример — уточнение о корректности, **а не операция, которой учат в видео**:

```cpp
int value = 0;
int* pointerToValue = &value; // Hold the address of value.
*pointerToValue = 10;        // Write to that valid location.
```

[00:01:23](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=83s) Чтобы задать порядок действий, вы пишете **инструкции программы**, то есть **statement**. Это действия, выраженные в исходном коде, а не машинные инструкции, о которых шла речь раньше. Теперь урок переходит к этому порядку.

## Добавим инструкции и посмотрим на их порядок

[00:02:46](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=166s) Инструкция с `std::cout` выводит видимую строку. [00:02:48](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=168s) Расширьте тело так, чтобы за сообщением шёл **перевод строки**, завершающий текущую строку вывода, а затем имя:

## Определим функцию, не вызывая её

[00:03:50](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=230s) **Функция** — это именованная последовательность инструкций, которую можно переиспользовать. **Определение** функции задаёт это имя и её **тело** — инструкции в фигурных скобках. Перенесём инструкции с приветствием в функцию с именем `f`, а в `main` оставим отдельное сообщение:

```cpp
#include <iostream>

void f()
{
    std::cout << "Hello World";
    std::cout << std::endl;
    std::cout << "Anton";
    std::cout << std::endl;
}

int main()
{
    std::cout << "main";
    std::cout << std::endl;
}
```

`void` означает, что эта функция ничего не возвращает. Пустые `()` означают, что она не принимает **параметров** — именованных входов функции. Определение создаёт именованную последовательность, но не запрашивает её выполнение.

[00:04:05](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=245s) Выполнение этих программ начинается в `main`, а не в той функции, которая первой стоит в исходном файле. [00:04:18](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=258s) Записанный запуск печатает только:

```text
main
```

[00:04:31](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=271s) Этот результат объясняет разницу между определением списка инструкций и его активацией. Пока в `main` никто не вызывает `f`, поэтому её инструкции с приветствием не выполняются.

<details>
<summary>Приведёт ли размещение определения f выше main к тому, что приветствие выполнится первым?</summary>

Нет. Позиция делает определение доступным, но не вызывает его. В этой программе выполнение начинается в main, а в main находятся только её собственные инструкции вывода.

</details>

## Вызовем функцию из main

[00:04:43](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=283s) Оставим определение `f` и добавим одну инструкцию после перевода строки в `main`:

```cpp
int main()
{
    std::cout << "main";
    std::cout << std::endl;
    f();
}
```

`f();` — это **вызов функции**: он запускает выполнение тела `f`. `main` — **вызывающая** функция, та, которая делает вызов. Место, где написано `f();`, — это **место вызова**.

[00:04:51](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=291s) В модели процессора из урока вызов передаёт выполнение первой инструкции `f`. Её тело выполняется инструкция за инструкцией. **Возврат** означает продолжение работы вызывающей функции после этого вызова. Эта модель объясняет поведение программы; она не обещает, что каждая инструкция исходного кода превращается ровно в одну машинную инструкцию.

[00:05:08](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=308s) Полный записанный запуск сначала печатает `main` и её перевод строки, а затем приветствие и имя из `f`. Реконструкция даёт:

```text
main
Hello World
Anton
```

Слово «Hello» в звуковом объяснении относится к инструкции с приветствием; в последующем пересказе оно прямо названо «Hello World».

## Вызовем одну и ту же функцию дважды

[00:05:23](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=323s) Переиспользуемую функцию можно вызвать более одного раза. Оставим одно определение `f` и добавим второй вызов:

    std::cout << "main";
    std::cout << std::endl;

Проследите выполнение, а не считайте два вызова одновременными:

1. [00:05:27](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=327s) `main` печатает своё сообщение и перевод строки.
2. [00:05:39](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=339s) Первый вызов передаёт выполнение началу `f`. Она печатает `Hello World`, перевод строки, `Anton` и ещё один перевод строки.
3. [00:05:56](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=356s) Когда в `f` не остаётся инструкций, она возвращается к **месту вызова** — точке в `main`, сделавшей именно этот вызов. Выполнение продолжается со следующей инструкции — второго вызова.
4. [00:06:12](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=372s) Второй вызов снова запускает `f` с её первой инструкции. Всё тело выполняется заново, затем происходит возврат после этого второго вызова. В `main` больше нет инструкций, поэтому программа завершается.

Вывод, который подразумевает это прослеживание:

```text
main
Hello World
Anton
Hello World
Anton
```

Фраза «последнее место вызова» означает вызов, который завершается. Первое обращение возвращается после первого вызова, второе — после второго. Каждое обращение выполняет одно и то же тело функции.

<details>
<summary>Если добавить третий f(); после второго, что повторится?</summary>

Приветствие, его перевод строки, имя и его перевод строки повторятся ещё раз. Сообщение из main не повторится, потому что его инструкции вывода находятся вне f и повторно не вызываются.

</details>

## Вложим один вызов функции в другой

[00:06:34](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=394s) **Вложенный вызов** происходит, когда вызванная функция вызывает другую функцию. [00:06:38](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=398s) Добавьте `B`, заставьте её печатать `B` и перевод строки, а затем вызовите `f`. Измените `main` так, чтобы он вызывал `B` вместо прямого вызова `f`.

Эта упрощённая реконструкция записи повторяет форму вызовов и возвратов [связанного закоммиченного примера функции](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/83e6302c9a3af2c28f3a17539cbdff6d63159ec8/en/05_programming_fundamentals/function_example_1/main.cpp). В том исходнике используется `main → b → a` и арифметика, поэтому это **связанное свидетельство, а не точная программа с приветствием**:

```cpp
#include <iostream>

void f()
{
    std::cout << "Hello World";
    std::cout << std::endl;
    std::cout << "Anton";
    std::cout << std::endl;
}

void B()
{
    std::cout << "B";
    std::cout << std::endl;
    f();
}

int main()
{
    std::cout << "main";
    std::cout << std::endl;
    B();
}
```

В этом примере функции определены раньше, чем используются. У `B` три инструкции: написать текст, написать перевод строки и вызвать `f`. Вызов — обычная инструкция программы, поэтому он участвует в той же упорядоченной последовательности, что и вывод.

Проследите полный управляющий поток:

1. [00:06:49](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=409s) Начинаем в `main`. Выполняем её инструкции вывода, затем доходим до `B();`.
2. [00:07:03](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=423s) Этот вызов передаёт выполнение первой инструкции `B`. Печатаем `B`, затем её перевод строки.
3. [00:07:14](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=434s) Третья инструкция `B`, то есть `f();`, передаёт выполнение первой инструкции `f`. Выполняются все инструкции вывода `f`.
4. [00:07:23](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=443s) Когда тело `f` заканчивается, происходит возврат к её вызывающей функции `B` — после вызова `f`. Этот вызов был последней инструкцией `B`, поэтому `B` тоже заканчивается.
5. Возврат в `main` после `B();`. Следующей инструкции нет, поэтому программа завершается.

Предсказываемый вывод реконструкции:

```text
main
B
Hello World
Anton
```

В записи этот последний пример объясняется прослеживанием выполнения. Предыдущие запуски и финальное прослеживание вместе устанавливают главное правило: выполнять инструкции по порядку внутри текущего тела, переходить по вызову в другое тело и возвращаться к вызывающей функции, когда это тело завершается.

<details>
<summary>Почему после завершения f выполнение возвращается сначала в B, а не сразу в main?</summary>

Именно B сделала активный вызов f, поэтому B — вызывающая функция для f. Завершение f продолжает B после этого вызова. Только когда сама B завершается, выполнение возвращается в main после её вызова B.

</details>
