# C++ statements and simple functions

[00:00:00](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=0s) This lesson connects readable C++ code to the order in which a program performs actions. You will start with one message, change its output step by step, and then organize the same actions into functions that can be called once, twice, or from another function.

The terms you will need are:

- **Machine code** is the processor's low-level instruction language. A **programming language**, here C++, lets you describe actions in readable source code. **Abstraction** means expressing low-level details through simpler concepts.
- **Memory** stores values. A **memory cell** is a location that holds data; an **address** identifies a location. A **processor register** is a small storage location inside the processor. A **variable** gives a program a name through which to work with a value.
- A **program instruction**, usually called a **statement** in English, expresses an action in source code. **Syntax** means the rules for writing that code.
- A **function** is a named, reusable sequence of statements. Its **definition** supplies the name and statements; its **body** is the code enclosed by curly braces, `{ }`. **main** is the special function where execution of these examples begins.
- A **function call** starts executing a function's body. The **caller** is the function making that call, and the **call site** is the place where it is written. **Returning** means resuming the caller after the call. **Control flow** is the order in which execution moves between statements. A **nested call** occurs when one called function calls another.
- A **console** displays text; the **terminal** shown in the recording provides that display and a place to run commands. A **string literal** is text written between double quotation marks.
- The **standard library** supplies common facilities. A **header** makes library declarations available; `#include <iostream>` includes the header used for console output. `std::cout` is the standard output stream, and `<<` sends the following value to it.
- A **newline** ends the current output line. `std::endl` writes a newline and flushes the stream, meaning it sends buffered output onward.
- A **comment** is source text ignored as code. `//` starts a comment that continues to the end of its source line.
- A **source file** contains the code you write. A **compiler** translates source code; **compilation** is that translation. A **linker** combines compiled code and required library code into an **executable**, a file that can be run. **Linking** is that combining step, and a **flag** is an option passed to a build command.
- `int` is C++'s integer type and the return type used for `main`. `void` as a function's return type means it returns no value. A **parameter** is a named input to a function; the simple functions here take no parameters.
- For the accuracy clarification below only, a **pointer** is a value that holds a memory address. Pointer operations are not taught in this video.

## Define a function without calling it

[00:03:50](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=230s) A **function** is a named sequence of statements that you can reuse. A function **definition** supplies that name and its **body**, the statements enclosed by braces. Move the greeting statements into a function named `f` and leave a separate message in `main`:

```cpp
#include <iostream>

void f()
{
    std::cout << "Hello World";
    std::cout << std::endl;
    std::cout << "Anton";
    std::cout << std::endl;
}

int main()
{
    std::cout << "main";
    std::cout << std::endl;
}
```

`void` means this function returns no value. The empty `()` means it takes no **parameters**, named inputs to a function. The definition creates the named sequence; it does not request execution of that sequence.

## Nest one function call inside another

[00:06:34](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=394s) A **nested call** happens when a called function calls another function. [00:06:38](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=398s) Add `B`, make it print `B` and a newline, then call `f`. Change `main` to call `B` instead of calling `f` directly.

This simplified recording reconstruction shares its call-and-return shape with the [related committed function example](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/83e6302c9a3af2c28f3a17539cbdff6d63159ec8/en/05_programming_fundamentals/function_example_1/main.cpp). That source uses `main → b → a` and arithmetic, so it is **related evidence, not the exact greeting program**:

```cpp
#include <iostream>

void f()
{
    std::cout << "Hello World";
    std::cout << std::endl;
    std::cout << "Anton";
    std::cout << std::endl;
}

void B()
{
    std::cout << "B";
    std::cout << std::endl;
    f();
}

int main()
{
    std::cout << "main";
    std::cout << std::endl;
    B();
}
```

The functions are defined before their uses in this sample. `B` has three statements: write text, write a newline, and call `f`. A call is an ordinary program statement, so it participates in the same ordered sequence as output.

Follow the complete control flow:

1. [00:06:49](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=409s) Begin in `main`. Execute its output statements, then reach `B();`.
2. [00:07:03](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=423s) That call transfers execution to the first statement of `B`. Print `B`, then its newline.
3. [00:07:14](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=434s) `B`'s third statement, `f();`, transfers execution to the first statement of `f`. Run all of `f`'s output statements.
4. [00:07:23](https://www.youtube.com/watch?v=Z8AFpeE7hOo&t=443s) When `f`'s body ends, return to its caller, `B`, after the call to `f`. That call was `B`'s final statement, so `B` now ends too.
5. Return to `main` after `B();`. There is no following statement, so the program terminates.

The predicted output of the reconstruction is:

```text
main
B
Hello World
Anton
```

The recording explains this final example by tracing execution. The earlier output runs and the final trace together establish the central rule: execute statements in order within the current body, follow a call into another body, and resume the caller when that body finishes.

<details>
<summary>When f finishes, why does execution return to B before returning to main?</summary>

B made the active call to f, so B is f's caller. Finishing f resumes B after that call. Only after B itself finishes does execution resume main after its call to B.

</details>
