# How integers are stored in bytes

[00:00:00](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=0s) The goal is to connect a row of filled and empty cells to an integer: first count the values one byte can hold, then combine bytes, write their bits in hexadecimal, and finally interpret negative values and arithmetic that exceeds the available width.

The vocabulary used throughout the lesson is:

- **Bit**: one binary digit, either 0 or 1. A **byte** is the group of eight bits used in this lesson. A **set** bit contains 1; a **clear** bit contains 0.
- **Positional numeral system**: a way of writing numbers in which each digit has a value determined by its position. The **base**, or radix, is the number of possible digits: binary has base 2, decimal base 10, and hexadecimal base 16.
- **Place value**, or weight: the multiplier belonging to a position. Positions are numbered from zero at the right; position `k` in base `r` has weight `r^k`. Here `^` means mathematical exponentiation, not a programming operator.
- **Unsigned integer**: an integer interpreted without negative values. A **signed integer** also represents negative values. **Width** is the number of bits available. `int` is the C++ integer type mentioned in the recording; its size is not fixed by this diagram.
- **Hexadecimal digit**: one of `0–9, A–F`. **Nibble** means four bits, so one byte has two nibbles. The prefix `0x` identifies hexadecimal notation and is not part of the value.
- **Most significant bit**: the bit with the highest positional weight; the **least significant bit** has the lowest weight. In **two's complement**, the highest bit has a negative weight and all the other weights remain positive. That highest bit is the **sign bit**.
- **Invert bits**: exchange every 0 with 1 and every 1 with 0. Inverting the positive magnitude and adding one produces its negative two's complement representation at the same width.
- **Carry**: an amount passed to the next higher position during addition. **Borrow**: an amount taken from a higher position during subtraction.
- **Truncation**: discarding positions outside the destination width. **Wraparound**: the resulting return to another value within the fixed-width range.
- **Overflow**: a mathematical result outside the representable range. The recording also uses **underflow** for falling below that range, with some variation in naming for signed examples.

## Bits and bytes

[00:00:00](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=0s) Start with eight cells. Each cell is a **bit**, a binary digit with two possible states; together these eight bits form a **byte**. Empty and filled cells are a model for those states.

[00:00:10](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=10s) An empty, or clear, cell means 0; a filled, or set, cell means 1. This makes **binary**, the base-2 numeral system, a natural notation for the pattern:

```text
eight clear cells:  00000000
a different pattern: 01010100
```

[00:00:18](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=18s) Eight positions cannot express arbitrarily large numbers. To determine the limit, first separate two questions: how many patterns are available, and what is the largest value among them?

## Counting values in any base

[00:00:33](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=33s) A **positional numeral system** assigns a weight to each digit position. Its **base** `r` specifies which digits may occupy a position: `0` through `r − 1`.

[00:00:39](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=39s) In **decimal**, base 10, three positions hold digits from 0 through 9. The largest number is 999. [00:00:51](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=51s) Each position has a fixed weight, so placing its largest allowed digit in every position maximizes the total.

[00:01:09](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=69s) Count the patterns in order:

1. Begin at `000`.
2. Increase the rightmost digit: `001, 002, …, 009`.
3. Continue into the next position: `010, 011, …`.
4. Finish at `999`.

Every integer in the range occurs, without gaps. [00:01:32](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=92s) There are **1,000 values**, including zero, even though the largest value is 999.

[00:01:43](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=103s) Each of `N` positions has `r` choices, independently of the others. Therefore:

```text
number of patterns = r^N
unsigned range     = 0 through r^N − 1

three decimal positions: 10^3 = 1000 patterns
largest value:            10^3 − 1 = 999
```

Why is the maximum one less than the number of patterns?

## Why hexadecimal place values match binary

[00:08:13](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=493s) The grouping works because hexadecimal place values coincide with every fourth binary place value:

```text
16^0 = 2^0 = 1
16^1 = 2^4 = 16
16^2 = 2^8 = 256
16^k = 2^(4k)
```

Moving one hex position to the left moves four binary positions to the left. The weight changes by a factor of 16.

[00:08:29](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=509s) Decimal does not offer the same one-symbol replacement for a nibble. Replacing F with the two characters `15` would introduce two decimal positions. For example, `F5` means `15 × 16 + 5 = 245`; the decimal string `155` means a different number.

[00:08:49](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=529s) You could write the nibble values separately as `[15, 5]`, but that is a list of group values, not the ordinary decimal notation for the whole number. Decimal has no single digit for fifteen.

## Reading negative numbers with twos complement

[00:12:14](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=734s) A **signed integer** must distinguish negative values from nonnegative ones. In **two's complement**, change only the highest positional weight: for an eight-bit value it is `−2^7 = −128`, while the lower weights remain positive.

```text

signed weight: −128 64  32  16   8   4   2   1
```

[00:12:44](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=764s) A pattern with its highest bit set is therefore negative. For example, read the named pattern E1 by the rule:


[00:13:04](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=784s) To construct a negative pattern, **invert** the bits of its positive magnitude—swap 0 and 1—and then add one at the same width. A clean derivation for −18 is:

[00:13:37](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=817s) The discussion of “all bits set,” −1, and 127 needs a precise distinction. The all-ones pattern is neither the most negative signed byte nor the largest positive signed byte:

```text

10000000 = −128 +   0 = −128
```

## Carries and unsigned wraparound

[00:16:17](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=977s) **Overflow** arises when the mathematical result exceeds the available range. [00:16:24](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=984s) In the fixed-width machine model, positions beyond the byte are discarded, and hardware can signal the range failure. The retained bits alone do not guarantee that the original mathematical result fits.

[00:16:39](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=999s) A **carry** passes an amount into the next higher position. At an individual binary position, `1 + 1 = 10`: write 0 in that position and carry 1 upward. With an incoming carry, `1 + 1 + 1 = 11`: write 1 and carry 1.

A simplified example makes the carry chain explicit:

1. Add 1 to the all-ones byte.
2. At the lowest bit, `1 + 1` writes 0 and carries 1.
3. Each remaining set bit plus that carry also writes 0 and carries 1.
4. [00:17:09](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1029s) The final carry reaches the position above the highest stored bit.

[00:17:15](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1035s) **Truncation** discards that ninth position:

```text
  11111111
+ 00000001
-----------
1 00000000    full mathematical sum: 256
  00000000    retained eight-bit result: 0
```

[00:17:25](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1045s) The portion outside the byte disappears. This is **wraparound**: the retained pattern returns to a value within the range. Ordinary whole-byte `1 + 1` is 2 and does not overflow; the repeated `1 + 1` steps here concern individual bit positions in a carry chain.

[00:17:30](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1050s) Subtraction has the corresponding borrow case. If the subtrahend is larger than the unsigned starting value, the mathematical result is below zero. A borrow reaches beyond the destination and only the low eight bits remain.

[00:17:40](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1060s) Thus the earlier `0 − 1` pattern reads as 255 when treated as unsigned. [00:17:53](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1073s) The recording calls this downward range failure **underflow**. “Unsigned wraparound below zero” describes the behaviour unambiguously.

## Signed overflow and the corrected sum

## One sign bit for the whole number

[00:20:42](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1242s) A two-byte signed value has sixteen positions but only **one sign bit**, the highest bit of the entire value. The highest bit of the low byte is an ordinary positive-weight position.

[00:20:49](https://www.youtube.com/watch?v=3HnvK8WrK4M&t=1249s) The final correction is the weight of that single highest position:

```text
eight-bit signed value:    highest weight = −2^7  = −128
sixteen-bit signed value:  highest weight = −2^15 = −32768

sixteen-bit value =
    −b15 × 32768 + b14 × 16384 + … + b1 × 2 + b0 × 1
```

Every `b` is 0 or 1. All lower positions keep their ordinary positive binary weights. The lesson ends with the same positional principle it began with: the pattern, its width, and its signed or unsigned interpretation together determine the value.
