# Configure G++ in VS Code

[00:00:01](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=1s) This lesson connects an already-installed C++ compiler to VS Code so that you can build the current source file, run its executable, and stop at a line to inspect execution. It starts with an existing program, rather than writing a new one. The central relationship is: **F5 selects a launch configuration; that configuration requests a compilation task; the task produces the executable that the debugger launches.**

The terms you will meet are:

- **Source file, compiler, and executable:** a source file contains program text; a compiler translates that text into a runnable executable, also called a binary. **GCC** is the GNU compiler collection; **G++**, invoked as `g++`, is its C++ compiler command.
- **Terminal, command, argument, and flag:** a terminal lets you enter commands. A command names a program to run; arguments supply its inputs and options. A flag is an option such as `-o`, which specifies an output file.
- **GDB, breakpoint, and stepping:** GDB is the GNU debugger, which controls execution. A breakpoint pauses before a marked line executes. Stepping executes the next line; **F10** performs the step used here.
- **MSYS2, MinGW64, and pacman:** MSYS2 supplies development environments and tools on Windows; MinGW64 is one of its Windows compiler environments. `pacman` is its package manager, used to install software. `which` locates a command's executable.
- **PATH:** an environment variable containing the directories searched when a command is entered by name.
- **Git, repository, and clone:** Git manages versioned files. A repository holds those files and their history; cloning makes a local copy of the repository.
- **VS Code, extension, and workspace:** VS Code is the editor; an extension adds capabilities such as C++ support. A workspace is the project folder opened in the editor. The **Command Palette** is its searchable command menu.
- **Task and launch configuration:** a task describes an action such as compiling. A launch configuration describes which executable to start and how to debug it. `preLaunchTask` connects a launch configuration to a task by its label.
- **JSON and configuration variables:** JSON expresses settings as named values, objects inside braces, and lists inside square brackets. **JSONC** is JSON with comments. A VS Code variable such as `${fileDirname}` is replaced with a value from the currently active file.
- **File basename, extension, relative path, and working directory:** the basename is the file's name; its extension is the suffix such as `.cpp`. A relative path is interpreted from a working directory, the folder in which a command runs.
- **C++ standard, toolchain, IntelliSense, and MSVC:** a standard defines a version of C++. A toolchain is the compiler and related tools. IntelliSense is the C++ extension's code analysis and completion support. MSVC is Microsoft's C++ compiler, associated with Visual Studio. A **header** is a file containing declarations that source files can include, such as a library's interface.

For the matching practical work, see the [compiler-install lab](../../../en/labs/common/05_compiler_install.md). The lesson assumes that the compiler and C++ extension are installed. It covers a single active source file and the connection between building and launching. Detailed debugger operation and the less important configuration fields are deferred.

## Find the compilation task

[00:05:39](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=339s) The program is built by the “G++ compile current file” task. In the inspected repository version its actual label is `gcc_cpp_current_file`. [00:05:59](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=359s) It is a task defined by the course configuration, rather than an inherent default. Its definition is one entry in the task list in `.vscode/tasks.json`.

The [related committed task file](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/fef337c86c73ec8d197461ffe9327d69612ab81e/.vscode/tasks.json) gives the relevant structure. This excerpt keeps the command's essentials and working directory, omitting additional flags and task bookkeeping:

```json
{
    "label": "gcc_cpp_current_file",
    "command": "g++",
    "args": ["${file}", "-o", "${fileBasenameNoExtension}.exe"],
    "options": {
        "cwd": "${fileDirname}"
    }
}
```

[00:06:14](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=374s) The **command** is the program to execute: G++. Its **arguments** are the values passed to that program, here arranged in an array. `${file}` expands to the currently active source file. The **flag** `-o` tells G++ to write its result to the filename that follows it. Consequently, the task builds the open source file and names the binary after that source.

The label is also the name referenced by `preLaunchTask`; spelling it identically joins the two definitions. The task can therefore be reached through F5's launch configuration.

## Align the editor with the compiler

[00:09:07](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=547s) The C/C++ extension's properties file supplies the editor's view of the **toolchain**, the compiler and supporting tools. **IntelliSense** analyzes source and provides completion and diagnostics using that view. The recording initially speaks about the “usual” compilation setup, then explains the effect on the editor and the standard it assumes.

[00:09:21](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=561s) A **C++ standard** is a version of the language and its library.
