# Настройка G++ в VS Code

[00:00:01](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=1s) Это занятие связывает уже установленный компилятор C++ с VS Code, чтобы вы могли собрать текущий исходный файл, запустить полученный исполняемый файл и остановиться на строке, чтобы посмотреть, как идёт выполнение. Занятие начинается с уже имеющейся программы, а не с написания новой. Ключевая связь здесь такая: **F5 выбирает конфигурацию запуска; эта конфигурация запрашивает задачу сборки; задача создаёт исполняемый файл, который запускает отладчик.**

Термины, с которыми вы встретитесь:

- **Исходный файл, компилятор и исполняемый файл:** исходный файл содержит текст программы; компилятор превращает этот текст в исполняемый файл, который также называют бинарником. **GCC** — это набор компиляторов GNU; **G++**, вызываемый как `g++`, — команда компиляции C++ из этого набора.
- **Терминал, команда, аргумент и флаг:** терминал позволяет вводить команды. Команда задаёт программу для запуска; аргументы передают ей входные данные и параметры. Флаг — это опция вроде `-o`, задающая выходной файл.
- **GDB, точка останова и пошаговое выполнение:** GDB — отладчик GNU, который управляет выполнением. Точка останова приостанавливает выполнение перед строкой с отметкой. Пошаговое выполнение исполняет следующую строку; **F10** выполняет используемый здесь шаг.
- **MSYS2, MinGW64 и pacman:** MSYS2 предоставляет среды разработки и инструменты на Windows; MinGW64 — одна из его сред компиляции для Windows. `pacman` — его менеджер пакетов, которым ставят программы. `which` находит исполняемый файл команды.
- **PATH:** переменная окружения со списком каталогов, в которых ищется команда, когда её вводят по имени.
- **Git, репозиторий и клонирование:** Git управляет версионируемыми файлами. Репозиторий хранит эти файлы и их историю; клонирование создаёт локальную копию репозитория.
- **VS Code, расширение и рабочая область:** VS Code — редактор; расширение добавляет возможности, например поддержку C++. Рабочая область — это папка проекта, открытая в редакторе. **Палитра команд** — её меню команд с поиском.
- **Задача и конфигурация запуска:** задача описывает действие, например компиляцию. Конфигурация запуска описывает, какой исполняемый файл стартовать и как его отлаживать. `preLaunchTask` связывает конфигурацию запуска с задачей по её метке.
- **JSON и переменные конфигурации:** JSON выражает настройки как именованные значения, объекты в фигурных скобках и списки в квадратных скобках. **JSONC** — это JSON с комментариями. Переменная VS Code вроде `${fileDirname}` подставляется значением из текущего активного файла.
- **Базовое имя файла, расширение, относительный путь и рабочий каталог:** базовое имя — это имя файла; расширение — суффикс вроде `.cpp`. Относительный путь интерпретируется относительно рабочего каталога, то есть папки, в которой выполняется команда.
- **Стандарт C++, тулчейн, IntelliSense и MSVC:** стандарт задаёт версию C++. Тулчейн — это компилятор и сопутствующие инструменты. IntelliSense — анализ кода и автодополнение от расширения C++. MSVC — компилятор C++ от Microsoft, связанный с Visual Studio. **Заголовочный файл** — файл с объявлениями, которые исходные файлы могут подключать, например интерфейс библиотеки.

Соответствующая практическая работа — в [лабораторной по установке компилятора](../../../en/labs/common/05_compiler_install.md). Занятие предполагает, что компилятор и расширение C++ уже установлены. Оно охватывает один активный исходный файл и связь между сборкой и запуском. Подробная работа с отладчиком и менее важные поля конфигурации отложены на потом.

## Проверить компилятор и отладчик

[00:00:01](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=1s) Сначала проверьте, находит ли терминал компилятор по его голому имени исполняемого файла. G++ — это команда компиляции C++: если ввести её без исходного файла, компилятор запустится, но не получит ничего для компиляции. В записанной проверке выводится:

```console
g++
g++: fatal error: no input files
```

Сообщение об отсутствии входных файлов и есть полезный результат: команда нашлась и выполнилась. Сообщение о том, что саму команду найти не удалось, указывало бы вместо этого на установку или PATH. Так мы проверяем доступность, а компиляцию программы пока не проверяем.

[00:00:19](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=19s) GDB тоже должен быть установлен. Отладчик — это инструмент, который запускает исполняемый файл и останавливает его для исследования, поэтому установка только G++ оставляет часть настройки, отвечающую за отладку, незавершённой.

[00:00:29](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=29s) В среде MinGW64 отладчик ставят через `pacman`, менеджер пакетов, а затем находят через `which`. Запись показывает именно эту последовательность «установить, затем найти»; ниже приведён конкретный пример для MinGW64, где имя пакета сверено с [записью пакета MSYS2 GDB](https://packages.msys2.org/packages/mingw-w64-x86_64-gdb), а не воспроизведённая посимвольно команда из записи:

```sh
pacman -S mingw-w64-x86_64-gdb
which gdb
```

1. Выполните команду установки в подходящей среде MSYS2.
2. Выполните `which gdb`, чтобы увидеть, где находится установленный отладчик.
3. [00:00:54](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=54s) Добавьте каталог с этим исполняемым файлом в PATH системы Windows, как вы делали для GCC. PATH — это список каталогов, по которым разрешаются команды вроде `g++` и `gdb`.

Путь, напечатанный в оболочке MSYS2, отсчитывается от структуры установки MSYS2. При правке PATH в Windows используйте соответствующий каталог Windows. Процессы сборки и отладки редактора тоже должны находить эти инструменты; находка GDB в одной оболочке не доказывает, что его найдёт любой процесс.

[00:02:16](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=136s) Когда компилятор, отладчик, расширение и скопированная конфигурация на месте, нажатие **F5** может собрать и запустить активную программу.

[00:02:36](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=156s) Первый вариант по умолчанию в демонстрации не подходит. Здесь имя определяет вариант запуска, а метка задачи — отдельное действие компиляции.

[00:02:46](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=166s) С выбранным вариантом GDB записанная проверка компилирует программу, запускает её и печатает её ответ. Это успешная сквозная проверка, а не просто обнаружение инструментов.

## Проследить за конфигурацией запуска

[00:03:10](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=190s) Теперь посмотрим, что именно делает F5. **Конфигурация запуска** — это именованный набор инструкций по запуску программы; F5 использует выбранную конфигурацию, а вы можете выбрать другую из доступного списка.

[00:03:34](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=214s) Эти пункты объявлены в `.vscode/launch.json`. JSON группирует именованные настройки в объекты, а объекты конфигурации — в список. [00:03:46](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=226s) Разобранный в записи пункт GDB Launch стоит в этом списке третьим. [Связанная зафиксированная версия файла запуска](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/c484907b6e6ac331c6ab4fe508ca432f6f2585d5/.vscode/launch.json) тоже содержит GDB третьим; её существенные поля:

```json
{
    "name": "(gdb) Launch",
    "program": "${fileDirname}/${fileBasenameNoExtension}.exe",
    "cwd": "${fileDirname}",
    "preLaunchTask": "gcc_cpp_current_file"
}
```

Это сокращённый фрагмент, а не полная конфигурация для замены.

[00:03:56](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=236s) Главная задача пункта запуска — выполнить программу по пути из поля `program`. [00:04:13](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=253s) Синтаксис с долларом и фигурными скобками обозначает **переменную конфигурации** — подстановку, которую разворачивает VS Code:

| Переменная | Значение при активном файле `D:/project/a.cpp` |
| --- | --- |
| `${fileDirname}` | Папка активного файла: `D:/project` |
| `${fileBasenameNoExtension}` | Его имя без расширения: `a` |
| Итоговое значение `program` | `D:/project/a.exe` |

Расширение `.cpp` принадлежит исходнику, а суффикс `.exe` обозначает исполняемый файл Windows. Один только знак доллара не означает «папку»: подставляемое значение определяется конкретным именем переменной. Эти значения совпадают со [справочником переменных VS Code](https://code.visualstudio.com/docs/reference/variables-reference).

[00:04:43](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=283s) Остальные поля настраивают отладчик и в основном приходят из создаваемого им шаблона. Разбирать их все — за пределами этого занятия. Следующее важное здесь поле — связь с компиляцией.

## Убрать шаг сборки и посмотреть на ошибку

[00:05:00](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=300s) **Задача** — это действие, определённое для выполнения редактором. В этой конфигурации `preLaunchTask` называет действие компиляции, которое должно завершиться до того, как отладчик запустит программу. Значение должно совпадать с меткой задачи.

[Связанный зафиксированный файл запуска](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/c484907b6e6ac331c6ab4fe508ca432f6f2585d5/.vscode/launch.json) содержит связь со сборкой. Сокращённые примеры ниже показывают исходное состояние и временную правку из видео; изменённое состояние подтверждается отметкой времени, а не заявлено в том коммите.

```json
{
    "program": "${fileDirname}/${fileBasenameNoExtension}.exe",
    "preLaunchTask": "gcc_cpp_current_file"
}
```

[00:05:16](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=316s) Удалите строку с `preLaunchTask` и сохраните. Промежуточный пункт запуска теперь только просит запустить уже готовый бинарник:

```json
{
    "program": "${fileDirname}/${fileBasenameNoExtension}.exe"
}
```

1. [00:05:19](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=319s) Удалите уже собранный исполняемый файл.
2. [00:05:23](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=323s) Нажмите F5.
3. Посмотрите на записанную ошибку: исполняемый файл не существует.

[00:05:28](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=328s) **Исполняемый файл**, или бинарник, — это запускаемый результат компиляции. Исходный файл по-прежнему существует, но после удаления шага сборки у F5 нет указания пересоздать бинарник. Запуск и компиляция — разные действия.

**Предсказание:** если вы убрали шаг сборки, но оставили более старый исполняемый файл, докажет ли успешный запуск, что скомпилирован ваш последний исходник?

<details>
<summary>Ответ</summary>
<p>Нет. Запуск мог бы выполнить старый исполняемый файл. Удаление в демонстрации делает заметным отсутствие шага компиляции. Для рабочего сценария «сначала собрать, потом запустить» оставьте задачу компиляции связанной через preLaunchTask.</p>
</details>

## Найти задачу компиляции

[00:05:39](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=339s) Программу собирает задача «G++ compile current file». В разобранной версии репозитория её фактическая метка — `gcc_cpp_current_file`. [00:05:59](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=359s) Это задача, определённая конфигурацией курса, а не встроенное значение по умолчанию. Её определение — одна запись в списке задач в `.vscode/tasks.json`.

[Связанный зафиксированный файл задач](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/fef337c86c73ec8d197461ffe9327d69612ab81e/.vscode/tasks.json) задаёт нужную структуру. В этом фрагменте сохранены существенные части команды и рабочий каталог, а дополнительные флаги и служебные поля задачи опущены:

```json
{
    "label": "gcc_cpp_current_file",
    "command": "g++",
    "args": ["${file}", "-o", "${fileBasenameNoExtension}.exe"],
    "options": {
        "cwd": "${fileDirname}"
    }
}
```

[00:06:14](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=374s) **Команда** — это программа для выполнения: G++. Её **аргументы** — значения, передаваемые этой программе, здесь собранные в массив. `${file}` разворачивается в текущий активный исходный файл. **Флаг** `-o` говорит G++ записать результат в имя файла, следующее за ним. Значит, задача собирает открытый исходный файл и называет бинарник по этому исходнику.

Метка — это ещё и имя, на которое ссылается `preLaunchTask`; одинаковое написание связывает оба определения. Поэтому задачу можно вызвать через конфигурацию запуска F5.

[00:06:37](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=397s) Остальные поля определения задачи для объяснения на этом этапе менее важны. Занятие не требует перечислять их по одному.

## Скомпилировать без запуска и найти результат

[00:06:46](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=406s) Задачи можно запускать и отдельно. Чтобы скомпилировать без запуска отладчика:

1. Оставьте нужный исходный файл активным.
2. [00:07:03](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=423s) Найдите **Run Task** в палитре команд — меню команд редактора с поиском. В нём перечислены две задачи из записанного файла задач.
3. [00:07:23](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=443s) Выберите задачу компиляции G++. Она выполняет настроенную команду компиляции без отдельного действия запуска.

[Связанное зафиксированное определение задачи](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/fef337c86c73ec8d197461ffe9327d69612ab81e/.vscode/tasks.json) связывает эти существенные аргументы с G++. [00:07:35](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=455s) Прочитайте получившуюся команду по порядку: компилятор, путь к текущему исходнику, `-o`, имя выходного файла. Для исходника с именем `a.cpp` упрощённое развёртывание выглядит так:

```sh
g++ D:/project/a.cpp -o a.exe
```

Полная зафиксированная задача содержит дополнительные флаги; этот пример выделяет только объясняемую связь входа и выхода.

[00:07:57](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=477s) **Базовое имя файла** — это имя файла, а удаление расширения превращает `a.cpp` в `a`. Конфигурация добавляет `.exe`, получая `a.exe`. Имя выходного файла — **относительный путь**, поэтому его место назначения тоже зависит от папки, в которой выполняется команда.

[00:08:06](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=486s) Демонстрация переносит исходник во вложенную папку и компилирует снова. [00:08:20](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=500s) Бинарник появляется рядом с этим исходником, сохраняя своё имя.

[00:08:27](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=507s) Это происходит потому, что **текущий рабочий каталог** задачи — папка, в которой выполняется её консольная команда. То же [зафиксированное определение задачи](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/fef337c86c73ec8d197461ffe9327d69612ab81e/.vscode/tasks.json) задаёт его явно:

```json
{
    "options": {
        "cwd": "${fileDirname}"
    }
}
```

Для активного исходника по пути `D:/project/nested/a.cpp` компилятор получает этот путь к исходнику, работает в `D:/project/nested` и записывает туда относительный выход `a.exe`. Путь запуска затем указывает на тот же бинарник. Именно привязка к папке исходника удерживает выход сборки и вход запуска согласованными при перемещении файла.

## Согласовать редактор с компилятором

[00:08:54](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=534s) Файл настроек не обязателен для объяснения сборки и запуска. В нём есть ассоциации, которые подсказывают редактору, как обрабатывать те или иные имена файлов и расширения. Короткий пример из [связанного зафиксированного файла настроек](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/cc744a22dcdfce37fa772561d7c9354af05b3b5a/.vscode/settings.json):

```json
{
    "files.associations": {
        "*.json": "jsonc"
    }
}
```

Здесь `jsonc` означает JSON с комментариями. Эти ассоциации не определяют команду компиляции, и занятие говорит, что пока их можно игнорировать.

[00:09:07](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=547s) Файл свойств расширения C/C++ задаёт представление редактора о **тулчейне**, то есть о компиляторе и вспомогательных инструментах. **IntelliSense** анализирует исходный код и даёт автодополнение и диагностику, опираясь на это представление. В записи сначала идёт речь об «обычной» настройке компиляции, затем — о её влиянии на редактор и о предполагаемом стандарте.

[00:09:21](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=561s) **Стандарт C++** — это версия языка и его библиотеки. [Связанный зафиксированный файл свойств](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/ec49d61932f626869f9cc0e4050733b56aba6696/.vscode/c_cpp_properties.json) выбирает C++20 для анализа в редакторе:

```json
{
    "configurations": [
        {
            "name": "Default",
            "cppStandard": "c++20"
        }
    ],
    "version": 4
}
```

В конфигурации Windows, обсуждаемой в записи, стандартные допущения редактора по умолчанию связаны с **MSVC**, компилятором Visual Studio от Microsoft. [00:09:42](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=582s) Если эти допущения не совпадают с вашим компилятором и стандартом, редактор может ругаться на возможности из более нового стандарта, даже если ваш тулчейн их поддерживает.

[00:09:55](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=595s) Показанная правка явно выбирает G++ в поле компилятора. Более ранняя [зафиксированная версия свойств](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/4548bceac3c7982861496f1d77d29ecb7eddf7a0/.vscode/c_cpp_properties.json) содержит `compilerPath` со значением по умолчанию; этой правки из видео там нет. Упрощённый фрагмент до и после:

```json
{
    "cppStandard": "c++20",
    "compilerPath": "${default}"
}
```

```json
{
    "cppStandard": "c++20",
    "compilerPath": "g++"
}
```

После правки переход к исходникам библиотек в записи приводит в установку G++. **Заголовочный файл** содержит объявления, которые подключают исходные файлы; здесь его расположение показывает, к библиотеке какого компилятора обращается редактор. [00:10:21](https://www.youtube.com/watch?v=lBVXv8Qaj9Y&t=621s) Указанный здесь компилятор определяет сведения о компиляторе, которые использует эта конфигурация редактора.

Не путайте две роли: `compilerPath` и `cppStandard` настраивают IntelliSense, а настоящая задача сборки по-прежнему выполняет собственные `command` и аргументы. Изменение только файла свойств не переписывает эту задачу и не добавляет флаг стандарта её команде компиляции. [Справочник настроек расширения C++](https://code.visualstudio.com/docs/cpp/customize-cpp-settings) подтверждает, что эти свойства управляют анализом в редакторе. Полный путь к компилятору — однозначный способ указать конкретную установку при настройке своей машины.

Итак, готовая настройка состоит из трёх связанных частей: задачи, создающей бинарник, конфигурации запуска, которая собирает его перед запуском, и анализа в редакторе, согласованного с нужным компилятором и версией языка. Подробные настройки отладчика и остальные поля задачи остаются за пределами этого занятия.
