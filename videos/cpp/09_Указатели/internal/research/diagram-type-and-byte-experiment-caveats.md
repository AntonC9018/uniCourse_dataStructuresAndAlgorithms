# Diagram, type, and byte-experiment caveats (859Y0Q8pyLg)

- Toy address vs real address: diagram literal `32` is illustrative only; the real address is the printed `0x…` value (ledger TP-032/TP-035, transcript ~368–413s). Note's `int* iad = &i; // do not substitute literal 32` preserves this correction; verifier run 460 confirmed the distinction.
- Toy diagram is a teaching layout, not an allocator rule: slots `32–35` (int), `36`-only (one-byte var in a four-byte slot), `40–47` (eight-byte value, 48 excluded — verifier session `ses_ee2940a22ffeoMxpWMD6RWjdnW` confirmed the "runs to 48" ledger text means 48 excluded). Gaps (e.g. 37–39) are not part of the one-byte object; placement can differ in real builds (ledger TP-056/TP-057; author consulted `basic.align`).
- "Empty" cells and drawing order: "empty" means zero-valued representation bytes in the simplified drawing, not unwritten storage; left/right box order carries no memory-order guarantee; the recording notes pointers occupy eight bytes on its machine while the drawing simplifies to four-byte slots.
- Four-byte `int` is a demonstration assumption, not a C++ guarantee (`basic.fundamental`); pointer size is separate from pointee size, so `int*` does not mean "a four-byte pointer."
- Partial-write correction that shaped the note: loose extraction phrasing (TP-067/TP-068, "clobbers the entire four-byte value" / byte "shifting" into garbage) was corrected to: a one-byte write changes only one byte but changes the whole int's interpreted value; a wider access outside the object is undefined behavior with no guaranteed "shifted" result (`basic.lval#11`). Mismatched pointer assignment is therefore a compile-time rejection, not a size coincidence.
- Byte-experiment arithmetic (little-endian only): `500 = 1×256 + 244` → bytes `244, 1, 0, 0`; low-byte write of `8` → `8, 1, 0, 0` → `1×256 + 8 = 264` (TP-074/TP-075; verifier confirmed `500 → 264` and `0x20 = 32`). `256` is the smallest value needing two bytes (`0, 1`); final `257 = 256 + 1` holds only after recompilation.
- Stale-binary caution at transcript ~1082s: the instructor noticed the edited program had not been recompiled, then recompiled before the `257` result (~1085s). Note preserves this as "running the old executable does not test a source-code edit."
- Scope boundaries recorded in the ledger and kept in the note: virtual memory and alignment mentioned only briefly; byte-level number encoding deferred to another video; the byte-cast is for layout understanding, and the lesson closes by returning to whole-`int` writes through `int*`.
