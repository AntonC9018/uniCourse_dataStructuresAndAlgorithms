# Указатели: доступ к переменной по её адресу

[00:00:05](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=5s) Этот урок строит указатель на базе обычных чтений и записей переменной. Сначала мы изменим целое число, обратившись к нему по имени, затем получим его адрес и, наконец, прочитаем и изменим то же число через этот адрес. Заключительный эксперимент объясняет, почему важен тип объекта, на который указывает указатель: изменение одного байта целого числа может оставить в памяти остальные байты прежнего значения.

Понадобятся следующие термины:

- **Ячейка памяти, байт и бит:** ячейка на схемах соответствует одному байту памяти. На показанной машине байт содержит восемь битов, каждый из которых равен либо 0, либо 1. **Двоичное представление** — это набор битов, используемый для кодирования значения.
- **Переменная, значение и присваивание:** переменная даёт имя объекту, у которого есть память; её значение — это данные, которые сейчас там хранятся. **Время жизни** объекта — период, в течение которого он существует. Присваивание заменяет эти данные. **Объявление** задаёт переменной тип и имя, а **инициализация** — её начальное значение.
- **Тип и `int`:** тип определяет, как представляются данные и какие операции допустимы. `int` — используемый здесь целочисленный тип, занимающий четыре байта на показанной машине.
- **Поток вывода:** `std::cout` получает значения для отображения через `<<`. `std::endl` завершает строку и сбрасывает буфер вывода.
- **Адрес, указатель и объект, на который указывают:** адрес идентифицирует место в памяти; указатель хранит значение адреса; объект, на который указывают, — это объект, достигаемый через указатель. `int*` означает «указатель на `int`».
- **Взятие адреса и разыменование:** унарный оператор `&` получает адрес объекта. Унарный оператор `*` переходит по указателю и даёт доступ к объекту, на который он указывает.
- **Шестнадцатеричная запись:** система счисления с основанием 16, использующая цифры 0–9 и A–F; префикс `0x` помечает шестнадцатеричное число в выводимых адресах.
- **Виртуальная память:** операционная система отображает адреса программы на физическую память. **Рандомизация адресов** может менять эти адреса от запуска к запуску.
- **Выравнивание:** тип может требовать, чтобы его память начиналась по достаточно кратному адресу. Кажущееся пустым пространство между объектами не становится автоматически частью значения ни одного из них.
- **Байтовый тип и проверка типов:** `uint8_t` — беззнаковый восьмибитный целочисленный тип (если он предоставлен) со значениями 0–255. **Компилятор**, переводящий исходный код в исполняемую программу, отклоняет обычные присваивания между несовместимыми типами указателей.
- **Приведение типа и порядок байтов little-endian:** приведение явно запрашивает преобразование типа. **Приведение в стиле C** записывает тип назначения в скобках перед операндом; **`reinterpret_cast`** — это синтаксис C++ для явного переинтерпретирования. **`unsigned char`** — беззнаковый символьный тип, допустимый для доступа к байтам. **Псевдоним** типа — другое имя того же типа. Порядок little-endian помещает младший байт многобайтового целого числа по наименьшему адресу.
- **Неопределённое поведение:** операция, для которой C++ не задаёт обязательного результата; доступ к объекту через неподходящий тип или за пределами его памяти может привести к этому.

Для связанной практики используйте лабораторию [Указатели](../../../en/labs/cpp/03_pointer.md) из репозитория. В ней есть упражнения сверх записанного материала; они необязательны для дальнейшего изучения.

**Область изложения.** Урок охватывает адреса, `int*`, `&`, чтение и запись через `*`, совместимость типов указателей и один явный эксперимент с приведением к байтовому указателю. Виртуальная память и выравнивание упоминаются лишь кратко. Подробное кодирование чисел отложено до отдельного видео. Эксперимент с записью по байтам нужен для понимания размещения данных, а не как рекомендуемый способ присваивания обычным целым числам.

Примеры ниже в упрощённом виде воспроизводят записанные состояния кода. Ссылки с отметками времени указывают на эти состояния. [Связанный сохранённый пример работы с памятью](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/eb8f41e0402f4552beec72bc0953b86251d16cf4/en/05_programming_fundamentals/memory_example_1/example.cpp) тоже показывает взятие адреса и разыменование, но использует другие значения и дополнительные операции; это не точная сохранённая версия данного видео. ## Чтение начальных переменных

[00:00:05](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=5s) Начнём с двух **переменных** — именованных объектов, в памяти которых хранятся их текущие **значения**. Каждое **объявление** задаёт тип и имя, а инициализатор — начальное значение:

```cpp

{

    int a = 5;

    std::cout << i << std::endl;

}
```

[00:00:14](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=14s) Операторы вывода печатают `10` и `5` в отдельных строках. **Поток вывода** `std::cout` принимает каждое значение через `<<`; `std::endl` вставляет перевод строки и сбрасывает поток. Каждый оператор завершается точкой с запятой, а фигурные скобки охватывают тело `main`.

[00:00:29](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=29s) Использование `i` в этом выражении вывода читает хранящееся в нём значение, поэтому на выход поступает `10`. Аналогично использование `a` даёт `5`. Оно не передаёт идентичность или адрес переменной. Объяснение подстановки значений в записи относится к `i = 10`; `a` остаётся равной `5`.

## Перезапись значения

[00:00:52](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=52s) **Присваивание** изменяет значение в уже существующей памяти. Вставьте `i = 15;` перед выводом:

```cpp
int i = 10;

std::cout << i << std::endl;

```

Проследите изменение по шагам:

1. Инициализация сохраняет `10` в `i`, а `5` — в `a`.
2. Присваивание перезаписывает `i` значением `15`; второго `i` при этом не создаётся.
3. Вывод читает текущее содержимое, поэтому для `i` получает `15`, а для `a` — `5`.

[00:01:08](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=68s) При компиляции компилятор переводит исходный код в исполняемую программу. Запуск изменённой программы выдаёт сначала `15`, затем `5`, что подтверждает перезапись. [00:01:17](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=77s) Эти операторы выполняются в порядке написания. Если перенести печать перед присваиванием, она прочитала бы старое значение.

[00:01:22](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=82s) В памяти может храниться и **адрес** — значение, идентифицирующее местоположение другого объекта. [00:01:29](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=89s) На схеме появляется ещё одна ячейка, и в неё записывается условный адрес `32`. Это операция над схемой, а не корректная инструкция C++ для получения указателя из целочисленной константы `32`.

[00:01:45](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=105s) **Указатель** — это значение, по которому объект доступен через его адрес. На схеме новая переменная хранит адрес `i`, поэтому `i` становится **объектом, на который указывают**, — объектом, достигаемым через указатель.

[00:01:58](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=118s) Схема изображает и обычные целые числа, и адреса числами; подразумеваемая интерпретация у них разная. [00:02:07](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=127s) Реальная память хранит наборы битов, а не миниатюрное место или переменную внутри другой ячейки. [00:02:15](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=135s) Хранящийся в указателе набор битов интерпретируется как адрес. Эта числовая модель объясняет отношения между сущностями, но указатели в C++ — отдельный тип, а не взаимозаменяемые обычные значения `int`.

[00:02:22](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=142s) Здесь целью является конкретно объект типа `int`. [00:02:30](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=150s) Взятие его адреса даёт указатель на это целое число, а не на неопределённый набор байтов.

[00:02:45](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=165s) Сохранённый адрес задаёт начальную позицию. Программе также нужен тип цели, чтобы понимать, какой объект обозначает доступ. [00:02:52](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=172s) В этой демонстрации `int` занимает четыре ячейки байтов, которые вместе представляют одно целое число. [00:03:00](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=180s) Поэтому `32` на схеме указывает на начало `i`, четыре байта которого расположены по адресам 32–35.

Соответствующий синтаксис можно посмотреть в [связанном сохранённом примере](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/eb8f41e0402f4552beec72bc0953b86251d16cf4/en/05_programming_fundamentals/memory_example_1/example.cpp); здесь упрощённое воспроизведение использует значение из видео:

Указатель хранит адрес. Тип цели известен из объявления; это не дополнительные данные о размере, хранящиеся рядом с адресом.

[00:03:21](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=201s) Обычное объявление `int` означало бы, что новая переменная хранит целое значение. Чтобы объявить указатель на целое число, добавьте звёздочку:

[00:03:44](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=224s) **`int*`** означает «указатель на `int`»: адрес, через который можно получить доступ к целочисленному объекту. [00:04:03](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=243s) `*` задаёт указательную часть, а `int` — тип объекта, на который указывают. Собственный размер переменной-указателя тоже отделён от размера объекта, на который указывают: `int*` не означает «указатель размером в четыре байта».

Одно объявление не даёт пригодного адреса цели; не читайте и не разыменовывайте этот неинициализированный указатель.

[00:04:22](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=262s) **Объявление** объединяет тип и имя переменной, а **инициализатор** может дополнительно задать начальное значение. ## Взятие адреса i

2. В `&i` оператор запрашивает местоположение объекта `i`.

[00:06:38](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=398s) Напечатанный адрес — это фактический адрес, использованный для `i` в данном запуске. Значение 32 на схеме было придумано для объяснения. Запись упоминает это отображение, оставляя подробный механизм за пределами урока.

## Запись через указатель

[00:07:37](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=457s) С переменной можно читать, записывать или взять её адрес. В демонстрации теперь ненужную `a` удаляют, а адрес `i` используют для изменения её содержимого.

[00:07:44](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=464s) Для записи по адресу используется **оператор разыменования** — унарный `*`. Он переходит по указателю и даёт доступ к объекту, на который указывают. [00:07:53](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=473s) Изменение выглядит так:

```cpp
int i = 10;
i = 15;
int* iad = &i;
*iad = 40;
std::cout << i << std::endl; // 40
```

[00:08:05](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=485s) Читайте `*iad` как «объект по адресу, хранящемуся в iad». Звёздочка здесь — оператор выражения, а звёздочка в объявлении `int* iad` образует тип указателя.

[00:08:17](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=497s) Проследите присваивание:

1. Прочитать адрес, хранящийся в `iad`.
2. Перейти по нему к объекту `i`.
3. Использовать этот объект как цель присваивания.
4. Сохранить там `40`.

[00:08:29](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=509s) В цели было `15`; запись заменяет его на `40`. Указатель по-прежнему содержит тот же адрес. [00:08:42](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=522s) Слева от знака присваивания `i` и `*iad` обозначают один и тот же целевой объект. Следовательно, `*iad = 40` здесь действует так же, как `i = 40`.

## Чтение через указатель

[00:09:02](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=542s) Разыменование даёт доступ к целевому объекту как для чтения, так и для записи. [00:09:15](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=555s) Замените прямой вывод `i` выводом `*iad`:

```cpp

*iad = 40;
std::cout << iad << std::endl;  // адрес

```

[Связанный сохранённый пример](https://github.com/AntonC9018/uniCourse_dataStructuresAndAlgorithms/blob/eb8f41e0402f4552beec72bc0953b86251d16cf4/en/05_programming_fundamentals/memory_example_1/example.cpp) тоже выводит значение по разыменованному целочисленному указателю; это связанный код, а не это точное состояние.

[00:09:37](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=577s) Переменная-указатель, использованная в выражении значения, даёт своё собственное хранимое значение — адрес. Если на условном примере в ячейке указателя показано 100, то чтение указателя даёт этот условный адрес, а не содержимое целого числа. Это не следует путать с выводом `40`, полученным через разыменование.

[00:09:57](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=597s) Выражение `*iad` сначала даёт доступ к целевому объекту; в выражении вывода затем читается его значение. [00:10:10](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=610s) С адресом 32 со схемы концептуальные шаги таковы:

1. Прочитать 32 из `iad`.
2. Перейти по адресу 32 к `i`.
3. Прочитать содержимое `i`, равное сейчас 40.
4. Передать 40 в поток вывода.

[00:10:17](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=617s) Взятие `&i` сохранило адрес в собственной памяти указателя. Чтение этого указателя и чтение объекта, на который он указывает, — разные операции. [00:10:27](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=627s) Поэтому чтение через `*iad` передаёт на вывод `40`.

## Почему байтовый указатель — другой тип

[00:10:47](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=647s) **Тип объекта, на который указывают,** сообщает программе, какого рода объект ожидает обращение. Урок противопоставляет четырёхбайтовый `int` и **`uint8_t`** — беззнаковое восьмибитное целое с диапазоном 0–255. На показанной машине он занимает один байт.

Мотивирующее изменение пытается передать целочисленному указателю адрес байтового объекта:

```cpp
#include <cstdint>

std::uint8_t a = 5;
int* iad = &a; // ошибка компиляции: несовместимые типы указателей
```

Именно это отклонённое состояние обсуждается в записи. Исходный тип `&a` — `std::uint8_t*`, а тип назначения — `int*`.

[00:11:07](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=667s) Представьте, что несовпадением пренебрегли бы. Чтение целого числа попыталось бы обратиться ко всему целому числу там, где существует лишь однобайтовый объект. Дополнительные байты этой переменной не принадлежат. [00:11:33](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=693s) Нельзя считать, что их содержимое равно нулю или имеет осмысленное значение. В реальном C++ такое неуместное обращение — это **неопределённое поведение**: язык не обещает даже конкретного «мусорного числа».

## Понимание схемы памяти

[00:11:40](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=700s) Схема использует **выравнивание** — требование к тому, где может начинаться память объекта, — чтобы объяснить промежутки между объектами. Она моделирует память четырёхбайтовыми слотами, оставляя неиспользованное место после однобайтовой переменной.

Это учебная схема, а не правило о том, что аллокатор размещает каждую переменную в четырёхбайтовом блоке или никогда не использует соседние байты для другого объекта. [Спецификация выравнивания C++](https://eel.is/c++draft/basic.align) определяет требования по типам; фактическое размещение может отличаться.

[00:11:54](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=714s) Условная схема выглядит так:

| Объект на схеме | Начальный адрес | Байты, принадлежащие объекту |
| --- | --- | --- |
| Четырёхбайтовое целое число | 32 | 32–35 |
| Однобайтовое целое в четырёхбайтовом слоте | 36 | только 36 |
| Восьмибайтовое значение | 40 | 40–47 |

Диапазон в восемь байтов заканчивается непосредственно перед 48; байт 48 в него не входит. Пространство 37–39 в этом рисунке не становится частью однобайтовой переменной.

[00:12:14](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=734s) У адреса тоже есть **двоичное представление** — набор битов, хранящихся в собственных байтах указателя. Схема распределяет небольшой адрес вроде 32 внутри более крупного слота. Для такого малого числового представления ненулевые биты нужны только в одном байте. [00:12:54](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=774s) То же упрощение применяется к небольшому целому числу вроде 15.

«Пустым» здесь называются байты представления с нулевым значением в упрощённом рисунке, а не отсутствующая память и не байты, которые обычное присваивание целого числа оставляет незаписанными. Порядок слева направо в рисунке не следует трактовать как гарантию порядка в памяти. Более поздний исполняемый эксперимент использует порядок little-endian. Запись также отмечает, что на её машине указатели занимают восемь байтов, хотя рисунок упрощён до четырёхбайтовых слотов.

[00:13:02](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=782s) Подробное кодирование байтов отложено до другого видео. Главная идея здесь — отличать байты, представляющие адрес, от байтов объекта, к которому этот адрес ведёт.

## Согласование указателя с объектом

[00:13:26](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=806s) Предположим, целочисленный указатель мог бы хранить адрес 36 со схемы. Обращение как к `int` ожидало бы четыре байта, хотя переменная, начинающаяся там, владеет лишь своим первым байтом. [00:13:44](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=824s) Байты вне объекта недоступны как часть его значения. [00:13:53](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=833s) Именно объявленный тип цели `int` у указателя означает, что обращение ожидает целое число. [00:14:14](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=854s) В этом примере это означает все четыре байта вместе, а не только тот первый байт, который случайно оказался полезным.

[00:14:37](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=877s) Чтобы обратиться к однобайтовой переменной как к самой себе, согласуйте указатель с её типом:

```cpp
std::uint8_t a = 5;
std::uint8_t* ap = &a; // подходящий тип
*ap = 15;             // записывает однобайтовую переменную
```

[00:14:52](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=892s) **Проверка типов** — это проверка компилятором того, подходят ли операции и присваивания под свои объявленные типы. Компилятор отклоняет и противоположное несовпадение:

```cpp
int i = 15;
std::uint8_t* ap = &i; // ошибка компиляции без явного приведения
```

[00:15:12](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=912s) Схема иллюстрирует две разные опасности. Запись через байтовый указатель в целое число изменила бы лишь один байт и сохранила остальные. Обращение к памяти байтового объекта как к целому числу означало бы более широкое обращение за пределы памяти этого объекта. Ни то, ни другое не следует считать безопасным неявным преобразованием.

[00:15:24](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=924s) Разговор о «порче всего числа» означает, что частичная запись меняет интерпретируемое значение целого числа. Настоящая однобайтовая запись **не** перезаписывает физически четыре байта. Аналогично, более широкое недопустимое обращение не имеет гарантированного сдвига или предсказуемого результата.

[00:15:32](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=932s) Обычное несовместимое присваивание указателей отклоняется компилятором до выполнения программы. Дело в типах и корректном доступе к объекту, а не только в размере: два несвязанных типа не становятся совместимыми лишь потому, что имеют одинаковый размер.

## Приведение к байтовому указателю

[00:15:35](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=935s) Теперь урок намеренно обходит обычную проверку присваивания указателей с помощью **приведения типа** — явного запроса на преобразование значения в другой тип. [00:15:44](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=944s) Оно интерпретирует адрес целого числа как байтовый указатель, поэтому обращение через этот указатель затрагивает один байт, а не целое число.

Упрощённое воспроизведение эксперимента с приведением:

```cpp
int i = 15;
int* iad = &i;
std::uint8_t* byte = (std::uint8_t*)iad;
*byte = 8;
std::cout << i << std::endl;
```

Тип в скобках в `(std::uint8_t*)iad` — это приведение в стиле C, показанное в данном воспроизведении. Оно меняет интерпретацию указателя; оно не превращает хранящееся целое в новый однобайтовый объект.

[00:16:06](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=966s) После записи по байту записанный эксперимент с небольшим значением читает обратно `8`. [00:16:16](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=976s) Объяснение зависит от **порядка байтов little-endian**: младший байт находится по наименьшему адресу, то есть это первый достигнутый байт. Начиная с небольшого значения 15, остальные байты целого равны нулю, поэтому замена младшего байта на 8 даёт чтение всего числа как 8.

Само по себе приведение типа не делает корректным произвольный доступ к типизированной памяти. C++ прямо разрешает доступ к представлению объекта через `unsigned char`; подход с `uint8_t` в видео опирается на то, что в его реализации этот тип является псевдонимом — другим именем того же типа — для `unsigned char`. Это различие следует из [правил доступа к объектам в C++](https://eel.is/c++draft/basic.lval#11) и [правил переинтерпретирования](https://eel.is/c++draft/expr.reinterpret.cast). Явно ориентированный на байты вариант того же воспроизведения:

```cpp
unsigned char* byte = reinterpret_cast<unsigned char*>(iad);
*byte = 8; // меняет один байт представления, а не весь int
```

Здесь `unsigned char` — тип для доступа к байтам, а `reinterpret_cast` — синтаксис явного переинтерпретирования указателя. Такое написание уточняет корректный вариант; оно не претендует на точное написание из записи.

## Почему 500 превращается в 264

[00:16:33](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=993s) Целому числу больше 255 нужно больше одного восьмибитного байта. В демонстрации начальное целое меняют на 500, оставляя ненулевой старший байт перед записью младшего байта:

```cpp
int i = 500;
unsigned char* byte = reinterpret_cast<unsigned char*>(&i);
*byte = 8;
std::cout << i << std::endl; // 264 на показанной схеме
```
Этот пример воспроизводит записанный эксперимент с использованием явно указанного типа для доступа к байтам. [00:16:49](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1009s) Вывод равен `264`, а не `8`.

На показанной четырёхбайтовой схеме в порядке little-endian проследите байты по возрастанию адреса:

1. `500 = 1 × 256 + 244`, поэтому его байты — `244, 1, 0, 0`.
2. Байтовый указатель достигает только первого байта.
3. Запись 8 меняет их на `8, 1, 0, 0`.
4. Чтение полного `int` даёт `1 × 256 + 8 = 264`.

Старший байт сохранил часть исходного 500. Запись его не обнулила. Выражение «перетекает в следующий байт» описывает то, как многобайтовый `int` представляет большее значение; присваивание слишком большого значения беззнаковому однобайтовому целому не записывает за пределы этого байта в соседний.

<details>
<summary>Почему предыдущая запись дала 8, а эта — 264?</summary>

У предыдущего целого во всех старших байтах был ноль. У числа 500 в следующем байте была единица, и однобайтовая запись оставила её без изменений.

</details>

## Почему следующий результат — 257

[00:17:45](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1065s) В обсуждении используется 256, чтобы особенно наглядно показать границу. Это наименьшее неотрицательное целое число, которому нужно больше одного восьмибитного байта. Его представление little-endian начинается с `0, 1`.

[00:18:05](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1085s) Более наглядное воспроизведение финальной записи младшего байта:

```cpp
int i = 256;
unsigned char* byte = reinterpret_cast<unsigned char*>(&i);
*byte = 1;
std::cout << i << std::endl; // 257 на показанной схеме
```

Тот же результат получится, если в примере с 500 старший байт останется равным 1, а запись младшего байта станет равной 1. [00:18:05](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1085s) Показанный результат равен `257 = 256 + 1`. Непосредственно перед этим, на отметке [00:18:02](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1082s), преподаватель замечает, что изменённая программа не была перекомпилирована. Исправленный результат получается после перекомпиляции: запуск старого исполняемого файла не проверяет правку исходного кода.

[00:18:11](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1091s) Запись по байту меняет только первый из четырёх байтов целого числа. [00:18:15](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1095s) Остальные байты остаются прежними. Замена одного байта не переносится на соседей, не увеличивает и не обнуляет их; это отличается от арифметических операций над всем целым числом.

<details>
<summary>Если старший байт остался равен 1, а младший стал 15, какое целое получится?</summary>

На этой схеме `256 + 15 = 271`. Сохранённый старший байт даёт 256 независимо от нового значения младшего байта.

</details>

## Возврат к записи целых чисел целиком

[00:18:23](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1103s) Эксперимент с приведением к байтовому типу нужен для понимания представления, а не для повседневных присваиваний целым числам. Работайте с целым числом через его собственный целочисленный тип.

[00:18:44](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1124s) Уберите переинтерпретацию байтов и вернитесь к `int*`:

```cpp
int i = 500;
int* iad = &i;
*iad = 8;
std::cout << i << std::endl; // 8
```

[00:19:01](https://www.youtube.com/watch?v=859Y0Q8pyLg&t=1141s) Поскольку `iad` — указатель на `int`, присваивание заменяет целое значение целиком. На показанной машине это записывает число по всем четырём байтам; никакой сохранённой старшей части от 500 не остаётся. Адрес в `iad` по-прежнему указывает на ту же `i`.

Теперь видна ключевая мысль урока: `iad` даёт адрес, а `*iad` даёт доступ к целому числу по этому адресу. Тип объекта, на который указывают, определяет, какого рода объект ожидает это обращение.
