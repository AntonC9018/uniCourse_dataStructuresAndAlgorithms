# Установка GCC и проверка программы на C++

[00:00:00](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=0s) Цель — установить тот же компилятор GCC для C++, что используется на курсе, превратить небольшой текстовый файл в запускаемую программу и сделать компилятор доступным по имени в консоли Windows. Использование примерно того же компилятора и той же версии уменьшает различия между сборками у разных студентов, но не гарантирует, что любая программа заработает на любой машине. Показанную установку можно выполнить без пароля администратора, если выбранное место установки и права учётной записи это позволяют.

По ходу изложения используются следующие термины:

- **Компилятор C++, GCC и g++:** компилятор переводит исходный код в программу, которую компьютер может запустить. GCC — это GNU Compiler Collection; `gcc` и `g++` — программы, которые управляют его инструментами компиляции. `g++` задаёт значения по умолчанию, подходящие для C++. **Компоновка (linking)** объединяет скомпилированный код с кодом библиотек, который ему нужен.
- **Стандарт C++ и тулчейн:** стандарт задаёт версию языка C++ и его библиотеки, например C++17. Тулчейн — это набор инструментов, используемых для сборки программ. **Готовый (prebuilt)** тулчейн уже скомпилирован за вас.
- **Архитектура:** платформа процессора, которую должны поддерживать загружаемые инструменты, например x86-64 для типичного 64-битного ПК на Windows.
- **MSYS2, MinGW и UCRT64:** MSYS2 предоставляет инструменты разработки для Windows и среду команд, похожую на Unix. MinGW/MinGW-w64 дают инструменты для сборки нативных программ Windows. UCRT64 — одна из доступных для выбора сред сборки MSYS2. Эти названия описывают связанные, но разные вещи.
- **Консоль, оболочка, Bash, Git Bash и cmd:** консоль — окно, в котором видны ввод и вывод текста; оболочка интерпретирует введённые там команды. Bash — оболочка в стиле Unix, Git Bash предоставляет среду Bash вместе с Git для Windows, а `cmd` — это командная строка Windows. Их настройки могут различаться.
- **Пакет и менеджер пакетов:** пакет — это набор ПО для установки. Менеджер пакетов загружает и устанавливает такие наборы; в MSYS2 используется `pacman`, который также применяется в Arch Linux.
- **Исходный файл, расширение, текстовый редактор и исполняемый файл:** исходный файл содержит текст программы, обычно с расширением `.cpp` для C++. Расширение — это суффикс после последней точки в имени файла. Текстовый редактор изменяет текст без форматирования документа. Исполняемый файл — это скомпилированный файл, который можно запустить.
- **Текущая папка, относительный путь, полный путь и аргумент командной строки:** текущая папка — рабочее расположение оболочки. Относительный путь интерпретируется от неё; полный путь задаёт расположение от диска или корня файловой системы. Аргументы — это текст, передаваемый после имени программы в команде.
- **Переменная окружения и PATH:** переменная окружения — именованная настройка, доступная работающей программе. PATH — список каталогов, которые оболочка просматривает, чтобы найти программу по имени. **Процесс** — это работающая программа, а **сеанс** здесь означает время жизни открытой оболочки.
- **set, echo и which:** `set` меняет переменную окружения cmd, `echo` выводит текст, а `which` сообщает путь к программе в среде Bash.
- **Fn-lock:** настройка клавиатуры, изменяющая поведение некоторых клавиш; она важна для сочетания клавиш вставки на показанной клавиатуре.
- **Заголовочный файл, функция и точка входа:** заголовочный файл предоставляет объявления, нужные для использования возможностей библиотек. Функция — именованный фрагмент кода, который можно вызвать. `main` — точка входа этой маленькой программы на C++: с неё начинаются её собственные инструкции. **Тип возвращаемого значения** описывает вид результата функции, **список параметров** — её входные данные, а **инструкция (statement)** — это команда в её теле.
- **Объект, поток, пространство имён и перегруженный оператор:** объект — это значение с типом и операциями; поток обрабатывает поток ввода или вывода. Пространство имён группирует имена, а перегруженный оператор придаёт символу оператора смысл для определённых типов. `std::cout` — объект стандартного потока вывода, а `<<` вставляет в него данные.
- **Строковый литерал, стандартный ввод и get:** строковый литерал — это текст в двойных кавычках. Стандартный ввод — обычный источник ввода программы, в этом примере обычно клавиатура. `std::cin` — объект этого потока, а `get()` читает один символ.
- **Скрытые файлы и Git:** скрытые записи — файлы или папки, которые Проводник может скрывать. Git — инструмент контроля версий, записывающий историю проекта; его каталог `.git` важен при подготовке Проводника к дальнейшей работе.

Практика находится в [лабораторной работе по установке компилятора](../../../en/labs/common/05_compiler_install.md). Эта заметка следует настройке GCC из видео, а не альтернативным вариантам установки компилятора, допускаемым в лабораторной.

**Объём занятия:** установить компилятор, создать и скомпилировать минимальную программу, запустить её, понять имена программ и аргументы, настроить PATH и добиться того, чтобы окно программы, запущенной двойным щелчком, не закрывалось. Более глубокое устройство потоков C++, пространств имён и перегрузки операторов остаётся на потом. Настройка сборки в редакторе и подробный разбор параметров компилятора выходят за рамки этого видео. Примеры ниже — короткие реконструкции состояний записи, а не утверждения о том, что в репозитории есть коммит с их точным текстом.

## Выбор и установка MSYS2

[00:00:15](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=15s) GCC знаком по разработке под Linux, и в записи инструменты для Windows описываются как предоставляющие похожую на Linux среду. Точнее, показанный установщик — это **MSYS2**, среда разработки для Windows; **MinGW-w64** предоставляет нативные тулчейны для Windows. Это не эмуляция операционной системы Linux. Кроме того, «изначально только для Linux» — неточная история: история релизов GCC начинается в 1987 году, до появления Linux. Полезный вывод состоит в том, что дистрибутив для Windows делает GCC доступным на Windows. См. [обзор MSYS2](https://www.msys2.org/) и [историю релизов GCC](https://gcc.gnu.org/releases.html).

[00:00:31](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=31s) Первый результат поиска, показанный в записи, датирован 2021 годом и отклонён как слишком старый для курса. Опасение касается поддержки **стандарта C++**: курс использует возможности новее C++17. Это предупреждение о конкретной загрузке, а не правило о том, что любой компилятор, выпущенный в 2021 году, поддерживает только C++17.

Следуйте записанной последовательности загрузки и установки:

В записи используется путь загрузки MinGW-w64/SourceForge для MSYS2.
2. [00:01:00](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=60s) Можно вместо этого перейти сразу на [MSYS2](https://www.msys2.org/). Скачайте установщик под **архитектуру** вашей машины, то есть поддерживаемую платформу процессора.

## Установка пакета компилятора

[00:01:56](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=116s) Откройте консоль MSYS2 из установленных ярлыков. Два способа запуска, сравниваемые в записи, в этой демонстрации приводят к одной и той же консоли, поэтому достаточно одного. Не обобщайте это на все ярлыки MSYS2: ярлыки для разных **сред сборки**, например UCRT64, выбирают разные настройки инструментов и пути поиска. Это объясняется в [документации по средам MSYS2](https://www.msys2.org/docs/environments/).

[00:02:05](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=125s) Эта специальная консоль нужна для однократной установки пакетов. После этого компилятор существует как программа на диске, и его можно вызывать и из обычной консоли Windows, при условии, что нужные файлы остались установленными и Windows может его найти.

1. [00:02:40](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=160s) Используйте `pacman` — **менеджер пакетов**, который устанавливает пакеты ПО за вас. В MSYS2 используется тот же инструмент управления пакетами, знакомый пользователям Arch Linux; устанавливаемый здесь набор ПО — это компилятор.
2. [00:02:52](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=172s) Скопируйте команду установки из описания к видео, а не перепечатывайте её. Устная транскрипция не сохраняет полную команду и имя пакета, поэтому здесь она не воспроизводится как точная команда.
3. [00:02:58](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=178s) Вставляйте с помощью **Shift+Insert**. На показанной клавиатуре **Fn+Esc** сначала отключает **Fn-lock** — настройку клавиатуры, изменяющую поведение клавиш, — чтобы сработало сочетание с Insert. Fn-lock относится к конкретной клавиатуре, а не к требованиям установки GCC.
4. Подтвердите запрос установки клавишей **Y**, затем **Enter**. Если в запросе показано `[Y/n]`, одной клавиши Enter достаточно, чтобы принять ответ по умолчанию «да». Дождитесь окончания установки пакета, прежде чем проверять компилятор.

Компилятор, установленный в записи, затем находится по пути `/usr/bin`. Выбор пакета важен: пакет MinGW-w64 для UCRT64 использовал бы вместо этого каталог данной среды. Согласуйте пакет компилятора, среду и каталог вместо того, чтобы считать, что в каждой установке одни и те же файлы.

## Запуск компилятора до изменения PATH

[00:04:53](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=293s) Первая проверка — можно ли вообще запустить компилятор. В консоли в стиле Bash на записанной машине ввод имени компилятора приводит к установленной программе. Ответ компилятора об отсутствии входных файлов всё же подтверждает, что он найден и запущен, но не подтверждает, что исходный файл успешно скомпилирован.

[00:04:55](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=295s) В показанной конфигурации `g++` доступен по имени через **PATH** консоли Bash — её список каталогов для поиска программ. Git Bash тоже может найти компилятор, если его собственный PATH содержит каталог компилятора; одной установки Git Bash для этого недостаточно. [00:05:05](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=305s) В новой оболочке **cmd** на этой машине имя не распознаётся. У разных оболочек могут быть разные значения PATH. [00:05:18](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=318s) Причина и постоянное исправление намеренно отложены до первой компиляции.

[00:05:21](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=321s) Найдите установленные программы. В записи `gcc` и `g++` обнаруживаются в `/usr/bin` внутри MSYS2, что при показанном корне установки соответствует `C:\msys64\usr\bin`. Здесь `usr` — имя каталога внутри MSYS2, а не папка профиля пользователя Windows. Это не универсальное расположение компилятора MinGW.

[00:05:45](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=345s) Используйте **g++** — программу GCC со значениями по умолчанию для C++. `gcc` тоже может компилировать исходники C++, но `g++` по умолчанию дополнительно настраивает **компоновку** с библиотеками C++, объединяя скомпилированный код с нужным кодом библиотек. Поэтому это удобный выбор для собираемой программы. См. [объяснение запуска g++ в документации GCC](https://gcc.gnu.org/onlinedocs/gcc/Invoking-G_002b_002b.html).

[00:05:51](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=351s) Когда программа недоступна по имени, вызывайте её по **полному пути**, то есть полному расположению вместе с именем исполняемого файла. [00:06:04](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=364s) Добавьте аргумент `--help`, чтобы запросить справку компилятора по командной строке. Этот реконструированный пример для cmd использует каталог из записи; подставьте свой путь:

~~~bat
"C:\msys64\usr\bin\g++.exe" --help
~~~

[00:06:12](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=372s) При простом запуске внешней программы оболочка читает первый элемент команды как имя программы или путь. Остальные элементы задают **аргументы командной строки** — текст, передаваемый этой программе. Кавычки удерживают путь с пробелами как один элемент; аргумент вроде `--help` просит компилятор выполнить определённое действие.

[00:06:16](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=376s) На этом этапе доступность программы по имени — всё ещё отложенный шаг. [00:06:26](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=386s) Полезная модель — «программа, затем аргументы»: оболочка запускает программу, а программа интерпретирует свои строки аргументов. Она не компилирует C++ только потому, что оболочка получила имя исходного файла. Экранирование и разворачивание аргументов — детали за пределами этой вводной модели.

## Пишем первую программу Hello World

[00:06:37](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=397s) Начните с небольшой программы, которая печатает узнаваемое сообщение. Ниже — упрощённая реконструкция этого состояния записи:

~~~cpp
#include <iostream>

int main() {
    std::cout << "Hello World";
}
~~~

Читайте новый синтаксис в порядке появления:

1. [00:06:45](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=405s) `#include <iostream>` делает доступными объявления из **заголовочного файла iostream**. Заголовочный файл предоставляет объявления для возможностей библиотек; этот даёт нам стандартные потоки ввода и вывода. Без подходящего объявления такое использование `std::cout` не скомпилируется. Существуют и другие средства вывода, но в этом примере используется iostream.
2. [00:06:54](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=414s) `int main()` определяет **главную функцию** программы, точку входа для её собственных инструкций. `int` — её целочисленный тип возвращаемого значения, `()` — список параметров, а фигурные скобки содержат тело функции. Дойти до конца `main` здесь допустимо и означает успешный возврат значения ноль.
3. [00:07:01](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=421s) `std::cout <<` использует **перегруженный оператор**: хотя `<<` — также символ сдвига влево, в этом потоке вывода его смысл — вставка. Префикс `std::` выбирает `cout` из **пространства имён** стандартной библиотеки — группировки имён.
4. [00:07:07](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=427s) Короткое выражение вывода опирается на абстракции: глобально доступный **объект** с именем `cout`, пространство имён и перегруженный оператор. Именно эти идеи объясняют, почему простая операция вывода поначалу может выглядеть сложной. Вывод на более низком уровне возможен, но требует деталей, которые это занятие не разбирает.
5. [00:07:24](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=444s) Думайте о `cout` как о месте, куда вы пишете информацию для консоли. Точнее, `std::cout` — это **объект стандартного потока вывода**, обрабатывающий исходящие данные; в этом примере он представляет вывод в консоль, а не само окно консоли. [00:07:29](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=449s) Запись в этот поток отправляет информацию к его назначению вывода.
6. [00:07:38](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=458s) Оператор вставки `<<` отправляет значение справа в поток слева. [00:07:48](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=468s) `"Hello World"` — **строковый литерал**, текст в двойных кавычках. Печатаются символы сообщения; кавычки обрамляют литерал и не печатаются. Точка с запятой завершает оператор.

Занятие использует этот синтаксис для проверки установки. Полное объяснение устройства объектов, пространств имён и перегрузки операторов относится к более поздним занятиям.

## Превращаем исходный текст в исполняемый файл

[00:07:54](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=474s) Сохранение исходного текста — не то же самое, что запуск программы. Сначала его нужно **скомпилировать**, то есть перевести в запускаемую форму. Концептуальные этапы для только что написанного исходника Hello World:

1. Сохранить текст в `.cpp`.
2. [00:08:02](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=482s) Запустить компилятор, чтобы получить **исполняемый файл** — итоговый файл, который может запустить Windows.
3. [00:08:06](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=486s) Запустить этот исполняемый файл — двойным щелчком либо вводом его имени или пути в консоли.

Редактирование исходника меняет входные данные компиляции. Оно не меняет автоматически уже лежащий на диске исполняемый файл.

## Компиляция и запуск из папки проекта

[00:08:13](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=493s) Сначала переведите оболочку cmd в папку с исходником. Это **текущая папка** — расположение, от которого оболочка интерпретирует относительные пути к файлам.

Следуйте первой последовательности компиляции:

1. [00:08:19](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=499s) Укажите полный путь к компилятору и передайте ему имя исходного файла как входные данные.
2. [00:08:31](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=511s) Чтобы получить путь к компилятору, перетащите его исполняемый файл из Проводника в консоль либо используйте **Shift+правая кнопка > Копировать как путь** и вставьте результат.
3. [00:08:44](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=524s) Добавьте имя исходного файла относительно текущей папки. **Относительный путь** интерпретируется от этой папки, поэтому `a.cpp` означает файл в папке проекта, а не в папке компилятора.
4. [00:08:54](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=534s) Выполните команду. Ниже реконструкция с путём и именем файла, обсуждавшимися в записи:

~~~bat
"C:\msys64\usr\bin\g++.exe" a.cpp
~~~

Если ваш исходник называется `main.cpp`, замените `a.cpp` этим именем. Путь к исполняемому файлу задаёт инструмент для запуска; путь к исходнику задаёт его входные данные. Они не обязаны находиться в одном каталоге.

[00:09:07](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=547s) Повторной компиляции в записи предшествует подготовительная команда в консоли, назначение которой отложено. Это временная настройка PATH, разобранная в следующих разделах: держите её в той же открытой консоли, следуя демонстрации, затем повторите компиляцию.

[00:09:13](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=553s) Компиляция создаёт **исполняемый файл**, который теперь можно запускать как программу. [00:09:24](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=564s) В таких простых командах первый элемент задаёт имя запускаемой программы. Чтобы запустить полученную программу из её папки в cmd, используйте имя её исполняемого файла. [00:09:37](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=577s) Наблюдаемый результат — в точности сообщение **Hello World**, что подтверждает и компиляцию, и запуск. Короткая реконструкция взаимодействия:

~~~bat
a.exe
~~~

~~~text
Hello World
~~~

[00:09:45](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=585s) Этот исполняемый файл можно также запустить из другой папки, указав его полный путь, точно так же, как вы делали для компилятора. Ниже то же действие с условным расположением проекта; подставьте своё имя учётной записи и свою папку:

~~~bat
"C:\Users\YourName\Desktop\cpp\a.exe"
~~~

<details>
<summary>Если ввести команду компиляции из другой папки, будет ли a.cpp по-прежнему указывать на тот же исходник?</summary>

Нет. Это относительное имя файла интерпретируется от новой текущей папки. Вернитесь в папку проекта или укажите полный путь к исходнику. Указание полного пути к компилятору не меняет способ разрешения аргумента с исходником.

</details>

## Пробуем временное изменение PATH

[00:09:56](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=596s) Каждый раз вводить полный путь к компилятору неудобно. Чтобы обращаться к нему просто как `g++`, добавьте содержащий его каталог в **PATH** — список каталогов оболочки, используемый для поиска программ.

Обсуждаемая здесь временная команда cmd ставит каталог компилятора перед существующим списком. Это реконструкция для записанной установки; используйте свой каталог компилятора:

~~~bat
set "PATH=C:\msys64\usr\bin;%PATH%"
g++ a.cpp
~~~

[00:09:56](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=596s) `set` меняет именованную **переменную окружения** — настройку, которую хранит работающий процесс cmd. `%PATH%` разворачивается в предыдущее значение PATH, а точка с запятой разделяет каталоги. Сохранение предыдущего значения сохраняет и другие места поиска программ. Это немедленно делает имя компилятора доступным в открытой консоли. Форма `set "NAME=value"` в кавычках удерживает присваивание вместе, не попадая кавычками в само значение. См. [документацию Microsoft по set](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/set_1).

[00:10:12](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=612s) Это изменение действует **только в текущем сеансе**: оно живёт столько же, сколько открытая оболочка. Новую настройку учётной записи Windows оно не сохраняет.

[00:10:19](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=619s) Запись демонстрирует это ограничение:

1. Закройте консоль.
2. Снова откройте cmd.
3. Вернитесь в папку проекта.
4. Ещё раз попробуйте имя компилятора.

Новая консоль больше не распознаёт `g++`, потому что временная запись PATH принадлежала закрытому процессу. Компилятор не удалён. Исчезла только настройка поиска этой консоли.

## Понимаем, как PATH находит компилятор

[00:10:45](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=645s) **PATH** — это переменная окружения, содержащая список путей к каталогам. [00:11:07](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=667s) Когда вы даёте имя программы, а не полный путь, оболочка использует этот список, чтобы найти исполняемый файл с таким именем. Для внешних команд в cmd текущий каталог проверяется раньше каталогов PATH; внутри PATH важен порядок каталогов. См. [документацию Microsoft о поиске по PATH](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/path).

[00:11:34](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=694s) Выведите текущее значение командой `echo %PATH%`. Здесь `echo` отображает текст, а `%PATH%` разворачивается в значение переменной. В записи показан длинный список записей, уже предоставленных Windows и установленным ПО:

~~~bat
echo %PATH%
~~~

[00:11:53](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=713s) Именно включение папки компилятора в этот список делает его имя пригодным для использования. Предыдущая команда поставила её в начало; эта демонстрация добавляет каталог в конец через точку с запятой. Обе команды добавляют место поиска, но позиция различается. Этот реконструированный пример сохраняет существующий список:

~~~bat
set "PATH=%PATH%;C:\msys64\usr\bin"
echo %PATH%
~~~

[00:12:08](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=728s) Во второй распечатке новая папка видна в конце. Это и есть результат проверки самого изменения переменной.

[00:12:17](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=737s) Теперь следуйте порядку поиска по имени, описанному в видео:

1. Введите имя компилятора.
2. Оболочка проверяет места поиска по порядку. В показанном PATH более ранние записи вроде System32 не содержат подходящего `g++`.
3. Поиск доходит до добавленного каталога компилятора и находит исполняемый файл.
4. [00:12:41](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=761s) Оболочка подставляет короткому имени полный путь к этому исполняемому файлу и запускает его.
5. [00:12:50](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=770s) Это та же самая программа компилятора, которую раньше запускали по полному пути. [00:12:52](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=772s) Затем уже компилятор, а не оболочка переводит исходный код, переданный ему как аргумент.

PATH — это список **каталогов**, а не список имён исполняемых файлов или исходных файлов. Если подходящий компилятор найдётся раньше при поиске, будет выбрана та программа.

<details>
<summary>Говорит ли добавление каталога компилятора в PATH также о том, где лежит a.cpp для g++?</summary>

Нет. PATH помогает оболочке найти программу компилятора. Относительный аргумент с исходником `a.cpp` по-прежнему разрешается от текущей папки. Это два независимых поиска.

</details>

## Сохраняем каталог компилятора в PATH

[00:13:01](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=781s) Чтобы не повторять временную команду в каждой новой консоли, сохраните каталог компилятора в настройках переменных окружения Windows. Сохранённая **переменная окружения** — это именованная настройка, из которой поздние процессы получают свои начальные значения.

1. Откройте **Панель управления > Система > Дополнительные параметры системы > Переменные среды** или найдите в меню «Пуск» **Изменение переменных среды для вашей учётной записи**.
2. [00:13:39](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=819s) Выберите подходящую область действия. **Переменные пользователя** применяются к вашей учётной записи; их редактирование подходит, когда у вас нет прав администратора. **Системные переменные** действуют для всех учётных записей и могут требовать учётных данных администратора.
3. [00:14:00](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=840s) Выберите существующую переменную **Path**, нажмите **Изменить**, затем **Создать**, чтобы добавить запись каталога.
4. [00:14:12](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=852s) Определите фактический каталог, содержащий ваш компилятор. Он зависит от места установки и выбранного пакета/среды; не копируйте путь только потому, что на другой машине использовали его.
5. [00:14:29](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=869s) Даже 64-битная установка из этой записи хранит компилятор в `usr\bin`. Здесь `usr` принадлежит дереву установки MSYS2, а не является папкой внутри Windows `C:\Users`. Сама по себе архитектура не определяет каталог компилятора.
6. [00:14:59](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=899s) Ищите компилятор в **каталоге bin** соответствующего установленного тулчейна — каталоге, содержащем его запускаемые инструменты. [00:15:07](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=907s) В консоли Bash, где компилятор уже находится, используйте `which` — команду, сообщающую, какой исполняемый файл выбрала оболочка по пути поиска:

~~~bash
which g++
~~~

Для записанной установки сообщаемый путь находится под `/usr/bin`. При корне установки `C:\msys64` содержащий его каталог — `C:\msys64\usr\bin`. Другой пакет может сообщить каталог вроде `/ucrt64/bin`. Переведите путь MSYS2 в его фактическое расположение в Windows; две эти записи пути в диалоге настроек Windows не взаимозаменяемы; см. [документацию MSYS2 о путях](https://www.msys2.org/docs/filesystem-paths/).

7. [00:15:23](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=923s) Вставьте **содержащий каталог**, а не имя исполняемого файла, в новую запись PATH. Используйте **Ctrl+V**, затем подтвердите кнопкой **ОК**.
8. [00:15:33](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=933s) Если в списке переменных пользователя нет переменной Path, создайте переменную с именем **Path** и укажите в её значении этот каталог. Если Path уже есть, добавьте в неё запись; не заменяйте существующее значение и не создавайте ненужную вторую переменную.
9. [00:15:45](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=945s) После сохранения закройте и снова откройте консоль. **Процесс** — это работающая программа; уже работающие процессы сохраняют свои собственные значения окружения, поэтому новая оболочка должна унаследовать обновлённую настройку от перезапущенного родительского процесса. Если она всё ещё наследует старое значение, перезапустите приложение терминала либо выйдите из учётной записи и войдите снова. В записи перед повторным открытием cmd требуется перезагрузка/перезапуск. См. [объяснение Microsoft наследования окружения](https://learn.microsoft.com/en-us/windows/win32/procthread/environment-variables).

Постоянное изменение сохраняет стартовое значение для будущих сеансов; оно не переписывает задним числом окружение уже открытой консоли.

## Проверяем компиляцию в новой консоли

[00:16:06](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=966s) Откройте новую консоль cmd, перейдите в папку с исходником и скомпилируйте по имени. Это реконструированная команда в той же простой форме, к которой приходит запись:

~~~bat
g++ a.cpp
~~~

Полный путь к компилятору больше не нужен, потому что эта новая консоль унаследовала сохранённую запись PATH. Относительное имя исходника по-прежнему зависит от того, что вы находитесь в папке проекта. Успешная компиляция подтверждает, что постоянная настройка пригодна к использованию, а не просто что диалог принял каталог.

## Не даём окну вывода закрыться

[00:16:25](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=985s) Запуск исполняемого файла двойным щелчком открывает для него консоль, печатает сообщение и закрывает окно, как только программа заканчивается. Быстрое мелькание окна не означает, что компиляция не удалась. Запуск из уже открытой консоли — один из способов прочитать вывод.

[00:16:42](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=1002s) Для показанного сценария с двойным щелчком добавьте операцию ввода после инструкции вывода. **std::cin** — объект стандартного потока ввода, в этом примере обычно получающий ввод с клавиатуры. Его операция **get()** читает один символ. Если символа нет, операция ждёт ввода, поэтому программа ещё не завершилась.

Финальное упрощённое состояние записи:

~~~cpp
#include <iostream>

int main() {
    std::cout << "Hello World";
    std::cin.get();
}
~~~

Скобки вызывают функцию `get` у `std::cin`; точка выбирает операцию этого объекта. Тот же заголовочный файл `<iostream>` предоставляет объявления стандартного потока ввода. Такое ожидание полезно для минимальной проверки, но это не универсальная функция управления окнами: если ввод уже доступен или закрыт, ожидания может не быть.

[00:17:15](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=1035s) Завершите финальную проверку:

1. Сохраните изменённый исходник.
2. Скомпилируйте его снова командой из предыдущего раздела; одного редактирования текста недостаточно для обновления исполняемого файла.
3. Дважды щёлкните по пересобранному исполняемому файлу.
4. Увидьте **Hello World** и окно, которое остаётся открытым.
5. Нажмите **Enter**. Ввод позволит `get()` завершиться; программа дойдёт до конца, и окно закроется.

Наблюдаемый результат подтверждает, что перекомпилированная программа включает добавленную операцию ввода.
