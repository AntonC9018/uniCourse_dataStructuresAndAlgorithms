The demonstrated installation can be done without an administrator password when the chosen installation location and account permissions allow it.

The terms used along the way are:

- **C++ compiler, GCC, and g++:** a compiler translates source code into a program the computer can run. GCC is the GNU Compiler Collection; `gcc` and `g++` are programs that drive its compilation tools. `g++` supplies defaults suited to C++. **Linking** combines compiled code with the library code it needs.
- **C++ standard and toolchain:** a standard specifies a version of the C++ language and its library, such as C++17. A toolchain is the collection of tools used to build programs. A **prebuilt** toolchain has already been compiled for you.
- **Architecture:** the processor platform the downloaded tools must support, for example x86-64 for a typical 64-bit Windows PC.
- **MSYS2, MinGW, and UCRT64:** MSYS2 supplies Windows development tools and a Unix-like command environment. MinGW/MinGW-w64 provide tools for building native Windows programs. UCRT64 is one of MSYS2's selectable build environments. These names describe related but different things.
- **Console, shell, Bash, Git Bash, and cmd:** a console is the window where text input and output appear; a shell interprets commands entered there. Bash is a Unix-style shell, Git Bash supplies a Bash environment with Git for Windows, and `cmd` is Windows Command Prompt. Their settings can differ.
- **Package and package manager:** a package bundles software for installation. A package manager downloads and installs those bundles; MSYS2 uses `pacman`, which is also used by Arch Linux.
- **Source file, extension, plain-text editor, and executable:** a source file contains program text, usually with the `.cpp` filename extension for C++. An extension is the suffix after the last dot in a filename. A plain-text editor changes text without document formatting. An executable is the compiled file that can be launched.
- **Current folder, relative path, full path, and command-line argument:** the current folder is the shell's working location. A relative path is interpreted from there; a full path identifies a location from the drive or filesystem root. Arguments are the text supplied after a command's program name.
- **Environment variable and PATH:** an environment variable is a named setting available to a running program. PATH is a list of directories searched when the shell needs to locate a program by name. A **process** is a running program, and a **session** here means the lifetime of an open shell.
- **set, echo, and which:** `set` changes a cmd environment variable, `echo` displays text, and `which` reports a program's path in the Bash environment.
- **Fn-lock:** a keyboard setting that changes how certain keys behave; it matters to the paste shortcut on the demonstrated keyboard.
- **Header, function, and entry point:** a header provides declarations needed to use library facilities. A function is a named unit of code that can be called. `main` is the entry point of this small C++ program: its own instructions begin there. A **return type** describes the kind of result a function returns, a **parameter list** describes its inputs, and a **statement** is an instruction in its body.
- **Object, stream, namespace, and overloaded operator:** an object is a value with a type and operations; a stream handles a flow of input or output. A namespace groups names, and an overloaded operator gives an operator symbol a meaning for particular types. `std::cout` is the standard output stream object, and `<<` inserts data into it.
- **String literal, standard input, and get:** a string literal is text written in double quotes. Standard input is the program's usual input source, normally the keyboard in this example. `std::cin` is its stream object, and `get()` reads a character.
- **Hidden files and Git:** hidden entries are files or folders Explorer can conceal. Git is a version-control tool that records project history; its `.git` directory is relevant when preparing Explorer for later work.

8. [00:15:33](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=933s) If your user-variable list has no Path variable, create a variable named **Path** with that directory as its value. If Path already exists, add an entry to it; do not replace the existing value or create an unnecessary second variable.
9. [00:15:45](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=945s) Close and reopen the console after saving. A **process** is a running program; already-running processes retain their own environment values, so the new shell must inherit the updated setting from a refreshed parent process. If it still inherits an old value, restart the terminal application, or sign out and back in. The recording calls for a reload/restart before opening cmd again. See [Microsoft's explanation of environment inheritance](https://learn.microsoft.com/en-us/windows/win32/procthread/environment-variables).

The persistent change saves a starting value for later sessions; it does not retroactively rewrite the environment of a console that is already open.

## Keep the output window open

[00:16:25](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=985s) Launching the executable by double-click opens a console for it, prints the message, and closes the window as soon as the program ends. A quick flash of a window does not mean compilation failed. Running it from an already-open console is one way to read the output.

[00:16:42](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=1002s) For the demonstrated double-click workflow, add an input operation after the output statement. **std::cin** is the standard input stream object, normally receiving keyboard input in this example. Its **get()** operation reads a character. With no character waiting, it waits for input, so the program has not yet finished.

The final simplified recording state is:

~~~cpp
#include <iostream>

int main() {
    std::cout << "Hello World";
    std::cin.get();
}
~~~

The parentheses call the `get` function on `std::cin`; the dot selects that object's operation. The same `<iostream>` header supplies the standard input stream declarations. This wait is useful for the minimal test, but it is not a general window-management feature: if input is already available or closed, it may not wait.

[00:17:15](https://www.youtube.com/watch?v=bQnbkV6xgY4&t=1035s) Complete the final test:

1. Save the changed source.
2. Compile it again with the command from the preceding section; editing text alone does not update the executable.
3. Double-click the rebuilt executable.
4. Observe **Hello World** and a window that stays open.
5. Press **Enter**. Its input lets `get()` finish; the program reaches its end and the window closes.

This observed result confirms that the recompiled program includes the added input operation.
